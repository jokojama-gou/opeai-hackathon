# 引き継ぎ・文書整合

このハッカソン向けの限定手順。[共通の使い方](../../../docs/development/aidd-lite/GUIDE.md)を確認し、現在の依頼と適用されるAGENTSを優先する。全skillの連続実行は要求しない。

## 手順と成果

- 現在の依頼、対象版・既存変更、成果、判断理由、証拠、残件を確認する。同じ依頼の継続・再開なら、明示済みの実行範囲と後続の取消・変更も記録して引き継ぎ、確認済みの了承を取り直さない。次の担当が正本へ辿れる短い記録を作り、詳細を複製しない。相手の環境だけにあるパスや読めない資料への依存を明示する。
- 判断変更や実装差分から正本・受入条件・テストの更新対象を照合する。GUIDEの反映手順に従い、許可外の文書は更新案として残す。
- 再開時は現在のファイルと対象版を照合し、古い記録を最新状態として使わない。分担対象・受け渡す成果・競合を明示するが固定役職や全員承認は増やさない。
- 成果はWORKFLOW様式に沿った記録と参照、反映待ち、環境不足、次の判断。同じ依頼の残作業と未依頼の候補を分け、終了した別作業の許可を新しい実行指示に変えない。

## 必要時に読む資料

- 製品の判断・共有・比較・デモに関係する場合：[プロジェクト固有の確認](../../../docs/development/aidd-lite/PROJECT_CHECKS.md)。
- 変更理由・由来を調べる場合：[出自](../../../docs/development/aidd-lite/PROVENANCE.md)。
