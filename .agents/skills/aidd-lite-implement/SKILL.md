# 実装・修正・検証

このハッカソン向けの限定手順。[共通の使い方](../../../docs/development/aidd-lite/GUIDE.md)を確認し、現在の依頼と適用されるAGENTSを優先する。全skillの連続実行は要求しない。

## 手順と成果

- 変更直前に実ファイル・適用指示・既存差分を再読する。実manifestや手順から確認方法を選び、架空コマンドを作らない。固定された不具合なら可能な範囲で再現→最小修正→同条件の再確認を行う。
- 他者の変更を保持し、競合時は最新内容を読み直す。独立作業を統合した後の動作も確認する。小さな表記変更には差分確認を用い、Story・ADR・無関係な全テストを要求しない。
- 実行結果を成功・失敗・未実行・実施不能・対象外に分ける。対象外は理由を付け、探索的観測は製品合格としない。同条件で同じ失敗を繰り返すときは根拠なく再試行せず、原因・再開条件を返す。
- 音声の利用条件は[VALIDATION](../../../docs/development/VALIDATION.md#音声の利用処理条件)を参照し、一般条件と既存4録音限定の例外を区別する。旧探索を自動再開しない。
- 成果は変更差分・確認と証拠・残件。仕様判断を伴った場合はGUIDEの反映手順を使う。

## 必要時に読む資料

- 製品の判断・共有・比較・デモに関係する場合：[プロジェクト固有の確認](../../../docs/development/aidd-lite/PROJECT_CHECKS.md)。
- 変更理由・由来を調べる場合：[出自](../../../docs/development/aidd-lite/PROVENANCE.md)。
