# 今回の書き起こしモデル：ElevenLabs Scribe v2

2026-09-15更新。ハッカソンのチーム向け説明です。

## まず知っておいてほしいこと

**音声の書き起こしを1つのモデルに絞るなら、ElevenLabsの「Scribe v2」（API上のモデル名は `scribe_v2`）を使う案を推奨しています。** 音声を文字にする処理をASRと呼びます。今回選んでいるのはASRであり、要約やAI会話を作るモデルは別の役割です。

Scribe v2は、録音を送ると、書き起こした文章に加えて「どの時刻に発言があったか」「どの話者の発言か」を返せます。日本語に対応し、単語ごとの時刻と話者分離を同じモデルで扱えます。[公式の機能説明](https://elevenlabs.io/docs/overview/capabilities/speech-to-text)、[対応言語の案内](https://elevenlabs.io/speech-to-text-api)。

声の事前登録は、ログイン不要の「iPhoneのひなた / Androidのごう」で登録音声を端末内に準備するところまで追加しました。外部照合は未接続です。[操作と制限](VOICE_ENROLLMENT.md)。

## なぜこれに絞るのか

私たちのアプリでは、文字を読むだけでなく、気になった発言から元の録音へ戻ることや、2人が録音した同じ会話を対応付けることを目指しています。そこで、文章・時刻・話者の情報をまとめて取得できるモデルが扱いやすいと考えました。これらは統合の材料になりますが、Scribe v2だけで2端末の会話統合が完成するわけではありません。

また、Scribe v2への接続はすでに実装してあり、人工音声で実際のAPI応答も確認しています。新しいサービスを追加するより、既存の経路を使って保存・共有の実装へ進みやすいことも選定理由です。全社へ同時に送り、結果を別のAIで比較する運用を通常の操作から外せば、設定・結果表示・失敗時の対応を減らせます。**精度比較で1位になったから選んだ、という意味ではありません。**

## 実際に使ったモデルと確認したこと

2026-09-15の検証では、ElevenLabsの `scribe_v2` に、Windowsで合成した日本語の人工音声7.522秒を送信しました。Nodeからアプリと同じ接続コードを呼び、書き起こしの取得に成功しています。記録上の所要時間は1,396ms、文字数は32、保存した単語区間は32件でした。これは短い人工音声1件の観測で、実際の会話での精度や応答時間を保証する数字ではありません。[当時の検証記録](../history/DIRECT_ASR_IMPLEMENTATION_20260915.md)。

現在の接続コードは、`https://api.elevenlabs.io/v1/speech-to-text` へ録音を送り、モデルに `scribe_v2`、言語に日本語、話者分離を有効にして要求します。返された文章・単語時刻・話者ラベル・元応答を保存します。録音の送信元は端末で、WindowsバックエンドによるASR中継を必須にはしません。[API仕様](https://elevenlabs.io/docs/api-reference/speech-to-text/convert)。

「話者0」「話者1」のようなラベルは、声を区別した結果です。誰の名前なのか、端末の持ち主が話したのか、別端末の話者0と同一人物なのかを証明するものではありません。本人・参加範囲・共有許可の確認はアプリ側で別に扱います。

> 書き起こしは、ElevenLabsのScribe v2に絞る案です。日本語の文章に加えて、発言の時刻と話者の区別も一緒に取れるので、原音への戻りや複数端末の記録を扱う基礎に使います。接続コードと短い人工音声での通信は確認済みです。今のアプリには複数社比較の動作が残っており、Scribe v2だけを使う切替と、実際のスマホ録音・共有統合の確認はこれからです。
