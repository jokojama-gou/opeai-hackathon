## 1. 現時点の推奨

**追記（今回の追加意向）: 1日で優勝を狙う開発では、複数モデルへ同じ音声を処理させ、得意な部分と誤り検出を組み合わせる案を優先する。** 全候補の検証完了を着手条件にしない。まず下のH01/H02/H03の小比較で、複雑化に見合う改善があるかを判断する。優勝や精度向上を保証するものではない。

**品質重視の第一比較対象は、ASRと話者処理を交換できる分業構成。対抗は、登録音声も使える統合サービスと、ASR・話者分離を同時に解くモデル。** 分業の方が必ず高精度とはまだ言えない。区間を切りすぎる、時刻を誤対応させる、といった結合部分の失敗で統合型に負けることもある。

最初の比較は次の順がよい。これは測定順の提案であり、性能順位ではない。

| 比較する仕事 | 優先候補 | 判断したいこと |
|---|---|---|
| 日本語ASR | GPT-Transcribe / Scribe v2 / Gemini 3.5 Transcribe / Qwen3-ASR-1.7B | 固有名詞・数字・否定・短い相槌まで残るか |
| 話者分離 | pyannote Precision-2 / Community-1 / 統合モデル内蔵の話者分離 | 同時発話・短い交替・端末の距離変化で誰の発言が欠けるか |
| 登録した本人との照合 | Precision-2 Voiceprint / ReDimNet2 B6の2学習版 / ECAPA-TDNN | 別日・別端末・未登録者での誤一致と保留の割合 |
| 統合型の対抗 | Scribe v2＋speaker library / GPT-4o Transcribe Diarize＋参照音声 / Gemini 3.5 Transcribe / VibeVoice-ASR | 分業の結合誤りを減らせるか。本人照合をどこまで内包するか |
| 日本語・ローカル補完 | ReazonSpeech K2 / Parakeet日本語版 / Nemotron-3.5-ASR / Whisper large-v3 | クラウド候補が落とす箇所を拾えるか。現行PC処理方針に適合するか |

時間を取れる比較では書き起こしは上位2モデル、話者分離は上位2方式、本人照合は上位2方式へ絞り、最後に組合せを測る。単体順位だけで最終構成を決めない。全モデルの総当たりより、誤りの原因を分離する比較を優先する。

### 1日で作る場合の構成と順序

| ID | 構成 | 役割と採用判断 |
|---|---|---|
| H01 | Scribe v2の時刻・話者付き書き起こし | まず動く基準。現在のMVPどおり本人は人が確認できる。これだけでも各端末入力→出典へ戻れる経路を作る |
| H02 | H01＋独立したGPT-Transcribe＋不一致区間の再認識 | **1日向けの第一推奨案。** 全文を別ASRでも認識し、単調な文字対応で食い違いを検出。Scribeの時刻を手掛かりに原音区間を切り出して再認識。第三のモデルは未解決箇所だけに追加する |
| H03 | H02＋Precision-2の話者分離、必要ならVoiceprint | 話者の取り違えが実際に減る場合に追加。Scribeの単語時刻に話者区間を重ねる。本人登録の工程は音声品質とは別に見積もる |

H02では**Scribeの時刻を、別ASRが出した文字へ無条件にコピーしない**。対応する区間だけに出典を付け、挿入/削除/境界の不一致は区間単位で扱う。対応不能は不明とし、必要な箇所だけ別alignmentを使う。ASR間で一致した部分も正解とは限らないので、評価では一致箇所の誤りも数える。

エラーチェックを次の3層に分ける。

1. ルールで時刻逆転・音声範囲外・空結果・不正な出典・異常な重複を検出する。
2. 独立ASR間の文字・重要語・否定の不一致と、話者推定の不一致を検出する。confidenceの数値は異なるモデル間で直接比べない。
3. 不一致区間だけ音声から再認識し、元候補との対応を残して選択する。文字しか見ないLLMが「もっとも自然な文」を作るだけでは音声の検証にならない。

最終統合は、選べる根拠がある候補を採り、未解決なら候補/話者不明を保持する。候補文字と原音・source/versionを失わない。モデル多数決、同じモデルの3回実行の多数決、すべての全文をLLMに渡して清書するだけの方式は、改善の対照としては測れるが最初の推奨にしない。

開発配分の案は、最初の1時間で静音・ポケット・重なり・専門語の4ケースをH01/H02で比較、次の2時間で2端末→本文→出典の縦の経路、次の2時間で不一致処理と必要な場合だけH03、残りを固定デモ・失敗表示・受入確認に使う。これは8時間程度の作業枠の提案で、実装時間の実測ではない。ローカル大モデルの導入やfine-tuningが長引く場合はその枝を外す。

並列処理の待ち時間は概ね最も遅い枝＋結合/再認識で決まり、費用は各枝の合計になる。再認識回数には実装上の上限を設け、無限に「念のため」を繰り返さない。原音送信先が増える影響は§9で確認する。

デモでは「A単独」「B単独」「統合」と、出典へ戻る操作を同じ会話で見せる。モデルをたくさん使ったこと自体より、片側の欠落を補えた件数、誤った確定を避けられた箇所、訂正にかかった時間を示す。実際に測れなかった効果はデモの主張に使わない。

## 2. 混同しない5つの仕事

| 仕事 | 答える問い | 単独では分からないこと |
|---|---|---|
| ASR | 何と言ったか | 発言者の本人ID |
| 話者分離（diarization） | 録音内で誰がいつ話したか | `speaker_0`が別録音の`speaker_0`と同一人物か |
| 話者照合・識別 | 登録したA本人か、候補の誰か、未登録か | 同じ会話か、端末所有者か、共有してよいか |
| 音源分離・対象話者抽出 | 重なった声を音として分けられるか | 分離後の声が誰か、言葉が正しく残ったか |
| 複数録音の対応・統合 | どの発言が同一で、片側の欠落を補えるか | 参加・共有の許可 |

1対1の声の照合と、候補者から選ぶ1対Nの識別も別評価にする。文章中の自己紹介や役割から名前を推測する機能は、声の特徴による照合とは別物。AssemblyAIのSpeaker Identificationは会話文脈・metadataを使うため、この区別が特に必要。[AssemblyAI公式](https://www.assemblyai.com/docs/speech-understanding/speaker-identification)

MVPは人が同一会話・本人帰属・参加範囲を確認する。自動本人識別が未達でも現在のMVP全部を止めない。話者推定を直接の共有認可にせず、派生情報にもD17の制約を適用する。

## 5. 構成パターンの全体像

「全パターン」は以下の主要方式と、入力数・処理順・登録の有無・後処理の軸で整理する。製品の全組合せを無条件に総当たりする意味ではない。

| ID | パターン | 強みの仮説 | 主な失敗・比較条件 | 優先 |
|---|---|---|---|---|
| P01 | ASRのみ＋人が話者/本人を確認 | 最短でMVPに接続、誤りの基準を作る | 自動識別精度の証拠にはならない。訂正時間も測る | 基準 |
| P02 | ASR＋diarizationの統合API/共同モデル | 発言と話者の結合誤りを減らせる | 1 APIでも内部は複数モデルの場合がある。本人IDは別 | 最初 |
| P03 | 統合型＋登録音声照合 | 工程が少なく、別録音の本人へ対応 | 参照音声長、未登録拒否、API機能・登録管理の制約 | 最初 |
| P04 | ASRとdiarizationを並列処理→時刻で結合→本人照合 | ASRの文脈を保ち各部品を交換 | alignmentで誤った文章にも時刻が付く。重なりへ単一話者を強制しない | 最初 |
| P05 | diarization→話者区間ごとASR→本人照合 | 話者別の認識条件を作れる | 短く切ると文脈/語頭を失う。paddingと重複除去を固定 | P04との比較 |
| P06 | 音源分離/対象話者抽出→ASR→照合 | 同時発話の両方を回収 | 分離アーティファクト、他人の声の漏れ。原音ASRも残す | 重なりで追加 |
| P07 | 同期した複数波形を融合・beamforming→ASR | 音としてSNRを改善できる | スマホ間の時計ずれ・残響・AGCが難所。mono平均は逆効果も | 後段 |
| P08 | 各端末ASR/話者処理→発言対応→選択・統合 | 片側で聞こえる言葉を使える。D03/D13に直結 | 端末を話者と同一視しない。重複、反復発言の消失、誤対応を測る | 最初 |
| P09 | 複数ASRの不一致箇所だけ再認識・原音照合 | 費用を許容し難所へ計算を集中 | 同じ系統の誤りに多数決は弱い。LLMが新しい文を創作しうる | 上位構成で追加 |
| P10 | 音声対応の汎用モデルへまとめて入力 | 文脈と音声を同時に扱える | 省略・補完・時刻誤り。本文の自然さで評価しない | 探索 |
| P11 | 辞書・ドメイン適応・fine-tuning | 専門用語や録音条件に適応 | テスト正解の漏洩と開発工数。まず辞書あり/なし、学習は後段 | 段階的 |
| P12 | streaming暫定結果＋終了後の高品質再処理 | 将来のライブ表示と最終精度の両立 | 暫定/確定版の整合と追加工数。ライブ表示は今回MVP外 | 後続 |

P08はP02〜P06と組み合わせられる。P09/P11は上位構成への追加条件。固定話者数/自動人数、参照音声なし/あり、raw/前処理後も別構成IDにする。「単一モデル対分業」の本比較はP02/P03とP04/P05を同じ入力で測る。

推奨する分業案は、各録音に対してASRと話者分離を実行し、ASRに時刻がなければ別のalignmentで対応付け、登録音声との照合後に端末間の同一発言を対応付ける構成。最終出力には元のsource ID/版/文字範囲と原音時刻を残す。音声時刻が取れない出力は不明とし、0秒や架空の時刻へ埋めない。[結合の公式例](https://docs.pyannote.ai/tutorials/diarization-asr-merge)、[MVP契約](../product/MVP_SPEC.md#contracts)

## 6. 比較実験の設計案

### 段階と終了条件

1. **ASRの予選**: 各端末単独と中央1台の同じ固定セットでASRを比較。話者情報を無視した認識精度、重要語、処理失敗から上位2〜3を選ぶ。辞書なしを共通基準、同一の事前用語集ありを別条件とする。
2. **話者分離/本人照合の予選**: ASRと独立した正解話者区間でも測定し、部品自体の強さを比較。その後、予測話者区間でも測って上流誤り込みの悪化を確認。
3. **構成の本比較**: 上位ASR×上位話者処理、統合型上位2、ローカル基準を同じ未使用セットへ適用。P08の統合、必要ならP09を追加。品質差・失敗率・訂正時間と60秒目標の実績を見て推奨構成を選ぶ。性能差が不明なら同点/追加確認とする。

探索セット案は12会話×約90秒、最終確認セット案は別の6会話×各5分以内。いずれもA端末/B端末/中央1台があるとよい。これは必要なデータの設計であり、収録を実施済みとはしていない。異なる配置・話者・別セッションを含める。合成音声はI/O確認には使えるが、声紋順位や本番会話精度の根拠にしない。

調整用と評価用を会話単位で分離する。同じ録音の切出し、同じ会話の別端末版を両方へ跨がせない。本人照合では登録用録音と試験録音を別セッションにする。最初は各候補1回、上位候補は同じセット3回を提案し、実行前に回数を固定する。追加の独立会話を増やすことと、同じAPIを繰り返すことを区別する。

### 正解と入力条件

- 人が音を確認して逐語文・話者・開始終了・重なり・聞き取り不能区間・端末間の同一発言IDを作る。モデル出力をそのまま正解にしない。可能なら別の人が争点を確認し、確定しない箇所は曖昧として残す。
- ASR単体は「その端末で聞こえる内容」、製品の統合は「許可された入力に存在する会話内容」で評価する。中央録音や他端末の正解をモデルのヒントへ混ぜない。
- 端末原本、decoder、sample rate/channel、再サンプル、VAD、gain/denoise、chunk長/overlap、language、辞書、話者人数、登録秒数を構成IDにひも付ける。前処理なしを基準に置き、denoiseの効果は独立比較。
- 人数既知の2人条件と人数未知条件を分ける。第三者混入ケースへ`num_speakers=2`を強制しない。
- 登録音声の公平比較は、まず各本人の同じ10秒・単独発話を使う案。短い試験発話（1秒未満、1〜3秒、3〜10秒、10秒超）を別集計する。10秒より長い登録で改善するかは別条件。
- 台本や正解全文をpromptへ渡さない。実験で渡す用語集は収録前に作り、含まれる語/含まれない語を別集計する。

## 7. 指標と判断方法

| 指標 | 定義・分母 | 注意 |
|---|---|---|
| 日本語CER | 文字の置換＋削除＋挿入 / 正解文字数 | strictと正規化後を別保存。NFKC・空白/句読点除去の固定版を使い、漢字を全部かなへ変えて誤りを隠さない |
| 重要語正答率 | 正しく回収した事前定義の重要語出現数 / 正解中の対象出現数 | 日付・数量・人名・否定。事後に得意な語だけ選ばない |
| DER | (話者混同秒＋見逃し秒＋誤検出秒) / 正解話者秒 | 0秒collar、overlap含むを主指標とする案。重なりは話者ごとの秒数。別設定の結果を混ぜない |
| cpCER | 話者ごとの文を結合し、話者ラベルの最良一対一対応で求める文字編集数 / 正解文字数 | 任意ラベルの入替は許すが、登録本人名の誤りは別評価。時間制約なしでは順序誤りを隠しうる |
| 本人ID付きCER | 名前の対応を固定した話者別文字誤り | cpCERがよくてもA/Bの本人を逆にした結果を見抜く |
| 1対1 FAR / FRR | 他人ペアを本人と受理した数 / 他人ペア数、本人ペアを拒否した数 / 本人ペア数 | thresholdは開発セットで決め、評価セットに固定。scoreが大きい方が類似かを記録 |
| 1対N本人正答率・未登録者誤受理率 | 正しい本人を選んだ既登録probe数 / 全既登録probe数、登録者の誰かにした未登録probe数 / 全未登録probe数 | 「不明」も残す。全件保留で誤受理ゼロだけを誇らない。候補人数を記録 |
| EER・minDCF | 同じ試行集合のscoreから別途算出 | 1対1の診断用。運用時の1対N誤受理と同一視しない。Excelの数件の率からEERを推測しない |
| 時刻・順序 | 人が確定した境界との差、逆転、対応不能数 | 同一入力の時刻と端末間時計補正を分離する |
| 統合品質 | 発言欠落、重複、新規誤り、片側発言回収の件数 | A単独/B単独/中央/統合を同じ会話で比較。最良単独超えの有無と悪化件数を両方残す |
| 性能・安定性 | 音声秒、wall time、RTF、成功/失敗/timeout、手修正時間 | RTFの分母は処理した入力音声秒の合計。2端末で分母が増えるのでwall timeも必須 |

DERは[pyannote.metrics](https://pyannote.github.io/pyannote-metrics/reference.html)、会議の話者付き文字誤りは[MeetEval](https://github.com/fgnt/meeteval)等を候補に、使用版・日本語文字分割・collarを固定して実装する。**Excelは編集距離や音声区間の採点エンジンではなく、外部で得た分子/分母を入力して率を比較する記入式の表**。CERとDERは100%を超えうるため上限で丸めない。

無音の正解文字数0はCER算出対象外で、挿入文字数/無音分を別記録。測定不能・非対応は未実行/実施不能/対象外とし、精度0%や成功へ変換しない。品質は共通に成功したケースの比較に加え、全予定ケースに対する失敗・欠測数を必ず併記する。API失敗を黙って除外しない。

総合点の重みと品質合格値は作らない。まず誤った本人帰属・未知者の誤受理・根拠のない追加発言を確認し、そのうえでASR/話者/訂正時間の改善を比較する。60秒は採用済みの目標で保証値ではない。既存の完了区間定義に加えて、音声処理だけの時間と利用者操作からの全体時間を別に測る。

差は会話ごとに対にして比較し、件数と改善/悪化の内訳を示す。信頼区間を出すなら会話単位のbootstrap等を使い、同じ録音から大量に切ったsegmentを独立標本と扱わない。少数の話者で誤受理0件でも将来の安全性を保証しない。「各会話で正解を見て最良端末を選んだ結果」はoracle参考上限であり、実装できた単独選択の結果とは分ける。

## 8. Excelの使い方

配布用ファイル名は `audio-model-comparison-20260913.xlsx`。タブは比較結果、声紋結果、構成案、モデル一覧、検証ケース。公開仕様と記入欄だけを含み、音声/認識文/声紋/測定結果は入れていない。

比較結果は同一の評価セット版・split・入力条件で1行を記入する。右側の黄色の欄へ分子/分母、予定/成功/失敗件数と証拠IDを入れると、左のCER/DER/cpCER/RTF/成功率が更新される。別セットや別設定で追試する場合は空いている行に構成IDと条件を入れる。事前に用意した行数を超える場合は表と数式範囲を拡張して確認する。

声紋結果は1対1と1対Nの試験数/誤り数を分けて入力。固定の同じthresholdと登録条件で比較する。生のscore一覧や音声からの指標算出はこのファイルに実装していない。閾値未確定でも探索結果は記入できるが、運用合格としない。

元データの保存/入力先は[音声利用条件](VALIDATION.md#音声の利用処理条件)に従う。表へ入力する証拠は匿名の評価IDを使い、内容を含む記録の所在と版は許可済みの保管場所で管理する。
