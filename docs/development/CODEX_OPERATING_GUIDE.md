## 使用ツールと確認状況

「資料で確認」は保存済み出典の記述。「提供を確認」はこのタスクのツール一覧で確認。「動作確認」は具体的な操作が成功した範囲のみ。いずれも将来の別タスクにおける可用性を保証しない。

| 手段 | 使用場面・選定条件 | 現状と根拠 | 入力・出力／代替・境界 |
|---|---|---|---|
| PowerShell・ファイル検索/読解 | 既存資料・対象コードの必要箇所を読む | 動作確認：本GoalでGet-Contentとファイル一覧・SHA-256取得成功。rgは利用時に確認 | パス・検索語→該当箇所。rgが使えなければSelect-String等。全文の無駄な再読を避ける |
| apply_patch | 文書や、将来許可されたコードの差分編集 | 動作確認：本Goalの文書追加・編集 | 最新内容に基づく差分→ファイル。適用失敗時は再読し、他者の変更を保持 |
| Web検索・Xブラウザ閲覧 | 現行仕様や本人記事の必要な不足を調べる | 提供を確認。先行調査の閲覧は独立資料に記録。本Goalでは追加閲覧未実施 | 公開の検索語/URL→根拠。私的な製品資料を検索語や外部送信に使わない。本文未取得は未確認 |
| CUAブラウザ操作 | 将来のUI調査・操作検証 | 提供を確認。ブラウザ用。現タスクのnative computer APIsは無効 | 許可されたURL・操作→画面/状態。記事の「全アプリ操作」を手元の機能と混同しない |
| シェルによるテスト実行 | 将来許可された実装・不具合の再現 | シェル提供を確認。製品のテストコマンド・環境は未確認 | 実manifest/READMEのコマンド→終了コード・対象結果。未導入なら導入済みとせず条件を提示 |
| サブエージェント | 独立レビューが明示許可された時 | 提供を確認。本Goalでは完成案1回＋重要変更時最大1回 | 原要求・制約・対象資料→具体的な指摘。Astra指定、文脈継承なし、再委任なし。利用実績はHANDOFFに記録 |
| Skills | 繰り返す特定手順に、既存の短い説明では不足する時 | 仕組みは資料で確認。多数のスキルが一覧にあるが関連性・実行は未検証 | 今回追加/導入しない。まず本ガイドの参照手順を利用。名称だけで起動しない |
| MCP・プラグイン | 必要な外部機能が通常手段で不足する時 | 個々の接続先・権限・製品適合は未確認 | 候補と理由を提案してから必要な導入判断。利用可能なツールの存在はデータ送信許可ではない |
| Goal | 終了条件の明確な複数工程を継続する時 | 本Goalのactive状態をget_goalで確認 | 明示された目的→進捗・完了。目標達成までの自律性と未決定仕様の決定権を混同しない |
| コンテクスト圧縮 | 長い会話の終了・引き継ぎ時 | 会話自体を任意圧縮する操作は本タスクのツール一覧で未確認。内容圧縮用ツールは別物 | 先に引き継ぎ保存。会話圧縮不可なら新しい会話で入口から再開。別サービスの内容圧縮で代替しない |
| コミット・PR・デプロイ・自動実行 | 将来明示的に依頼された場合 | 本Goal対象外・未実施 | 本書から起動・公開・スケジュールの許可を推定しない |

## モデル・推論量・文脈の扱い

- モデルの指定は現在の依頼に従う。過去の主担当Astra指定を他の作業へ継承しない。記事にあるLight等の表示と、現環境の設定値を同一視しない。
- 最高設定を常用すれば品質や費用効率が上がるとはしない。現在の選択を尊重し、変更が必要なら対象の難しさ・失敗・待ち時間を根拠に提案する。今回、推論設定の変更やモデル比較はしていない。
- コスト節約は、対象を絞る・既知資料を再利用・無関係な委任をしない・成功済チェックを繰り返さない方法で行う。最低限必要な確認を省略する理由にはしない。
- トークン数の厳密な上限は指定なし。Goalの予算を独自設定しない。金額やサブエージェント分の計測範囲が不明なら推定値を実測と表示しない。
- 会話全体を渡さない独立レビュアーには、重要な制約や最新決定も明記する。短縮によって必要な権限境界が消えることを防ぐ。

## 今回採用しないもの・次の適用時に決めるもの

本書は道具の参考で、製品の採用方式はMVP_SPECとロードマップが定義する。自動並列実装・多数のskill・定期自動化は本書から必須化しない。実行する道具は現依頼の目的・権限・費用と利用可能性に照らして選ぶ。

受け手向けの内容確認手順はルートREADMEを参照する。基盤の実利用確認は依頼者が終了と判断した。過去の試験を自動再開しない。
