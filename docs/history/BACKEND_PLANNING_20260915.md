## すでに決定済みで、決め直さなくてよいこと

[MVP_SPEC](../product/MVP_SPEC.md) §9/16と[PRODUCT_CORE](../product/PRODUCT_CORE.md)が正本。

- 当日必達は、2人の記録を許可範囲で統合し、根拠へ戻り、その記録でAIと会話すること。
- 端末→共通API→worker→外部ASR/文字生成。Supabaseは認証・DB・非公開保存を担当する。
- 同一会話、録音所有者、発言者、参加範囲、共有許可を別情報として持つ。自動本人識別は初回に追加しない。
- 原音7日、文字・派生物原則30日。期限・取消・訂正は生成入力全体と派生出力にも適用する。
- ルームは確認済みの会話相手が単位。相手本人へのDMではなく、本人用のAI会話。

## 実装の進め方と終了条件

1. **現行仕様へ合わせる（K01/K03/K04）**：旧処理同意の必須入力・判定・画面導線を移行。共有許可・所有者・版・期限・宛先設定の検査を保持。schema→OpenAPI→TSクライアント→画面の同一契約を照合し、既存DBの移行も扱う。
2. **1台の縦の経路を通す（K03）**：録音→認証付きupload→job→ASR→Source→原文表示。人工adapterで重複送信、部分失敗、結果不明、処理中削除、期限到達を確認。その後、確定した実行条件で1台の実録音を検証する。
3. **2台の中核を通す（K04/K05/K06）**：2アカウントの同一会話確認→双方許可→時間対応/重複・相違の統合→閲覧者別Context→根拠・clip。各統合箇所から両方のSource/版/区間へ戻れること。片方の許可取消・入力削除後に、禁止範囲の本文や派生結果を返さないこと。
4. **AI会話を接続する（K01/K09/K10、M15）**：参照・履歴判断後に契約と人工fixtureを作り、参照選択→質問→job→根拠付き回答を接続。生成前と保存/表示前に参照全体を再検査。根拠不足、空参照、通信断・二重送信、失効した過去回答を確認する。
5. **当日経路を両OSで通す（K07）**：iPhone＋AndroidでログインからAI回答の根拠確認まで実行。待ち時間・失敗箇所・費用を記録し、再起動/再接続を確認。PWAを使う場合はWeb録音の形式・HTTPS・CORSも実際の配信経路で確認する。

ASR選定待ちでも、1と人工adapterによる2/3、M15の設計案は進められる。M15の判断待ちで録音・共有実装全体を止めない。段階ごとに小さな承認を取り直すのではなく、許可された成果を完了まで進める。
