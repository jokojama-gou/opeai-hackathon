## 3. 比較・正解・反復の共通ルール

- 同じ録音組のA単独、B単独、人が両方を確認した結果、自動統合を区別。3台以上では各端末単独を残す。
- 改善・悪化をA/Bそれぞれに対して出す。都合の悪い単独結果だけを基準にしない。事後的に最も良かった単独結果との比較も併記する。
- 中央1台との比較は追加端末を確保した拡張段階で行う。最初の2台試験では中央録音への優位性を主張しない。
- 正解は実際の発言、話者、時刻、会話の組、参加イベントを人が確認して作る。台本の読み間違い・言い換えは実発言に合わせる。
- 正解不明は別集計し正答率の分母と区別。両入力で欠けた内容を台本から補っても、録音による回復には数えない。
- 評価者に正解や他条件の回答を先に見せない。可能なら別担当・別会話を割り当てる。同じ人が順次聞く場合はA先行/B先行を交互にし、記憶の影響がある探索と明記する。
- 短時間の各条件は異なる内容で3組、1組60〜120秒。2組を調整用、1組を未使用確認用に事前分割する。1組は同時記録した全端末分。同じ録音の再処理で録音組数を増やさない。
- 各条件の最初の1組で入出力を点検し、測定可能なら残りを収集。非決定的な処理は同じ設定で3回、決定的な処理は1回実行し全試行を残す。
- 改善は原因仮説を1つずつ変更し、調整用で最大2巡。未達なら方式比較または範囲判断へ戻す。技術的に不可能という結論ではない。
- 最終候補を未使用の1組で確認。再調整する場合はその組を調整用へ移し、新しい確認用1組を用意する。少数例から全体精度を保証しない。
- 端末・アプリ・形式、配置、実距離、雑音、入力ハッシュ、コード/方式/設定、試行ID、分割用途、正解作成法、結果件数を記録。音声・転記・正解の内容はPC内、Codexには匿名IDと集計値のみ。

| 指標 | 定義 |
|---|---|
| 重要事項の回復 | 決定・変更・理由・発言者・実施報告を別項目として正答/誤答/不明を集計。分母は正解が確定した対象項目数 |
| 補完と悪化 | 単独で不明・誤答だった項目の回復と、単独で正しかった項目が統合で誤答・不明になる件数を分ける |
| 発言の扱い | 正解の発言単位で欠落・重複・誤内容・話者取り違え・未判定を記録。創作された余分な発言は追加件数 |
| 根拠 | 回答が参照する発言・時刻の一致数/回答数。答えが合っていても根拠違いは別記 |
| 時間 | 入力準備・機械処理・手動確認を分離。機械処理は入力受付から結果確定まで、初回と反復を分ける |
| 失敗・保留 | 全試行を分母に入力不備・実行エラー・対応不能・判定保留を分離。無音や別会話に対する未判定を一律失敗にしない |

| 観測結果 | 次の行動 |
|---|---|
| 人が両方を使うと補完できる | A04〜A08で自動化を切り分け、A09/A11の未使用確認へ |
| 人には補えるが自動処理は失敗 | 正解の時間・話者・転記を1要素ずつ代入し、誤差の入口で最大2巡改善 |
| 両方で情報が失われている | A03で配置・収音を1因子ずつ変更。改善しなければ条件と限界をP4へ |
| 両単独で十分、追加価値が見えない | 想定場面の距離・移動・話者混同を確認。意図的に劣化加工した音声は診断用とし、実利用価値の証拠にしない。差がなければ差なしとしてP4へ |
| 内容補完はないが話者・根拠に改善 | A07/A09でその価値を独立評価。MVP採用はP4で判断 |
| 単独より悪化、別会話混入、創作 | 悪化項目を残しA04〜A08へ。平均改善で相殺しない。未解消なら方式/範囲判断へ |
| 正解や条件が不明 | 判定不能。正解作成・条件統一へ。成功にも技術失敗にも数えない |
| 未決定仕様に到達 | 該当O、候補・影響・推奨を提示。依存する合否判定だけ待ち、独立した整理は続ける |
| 人工データ/正解代入でのみ成立 | 部品の成立として記録。実録音を通す全体検証を残し、手動部分を明示 |
| 2巡でも未達 | 無期限に調整しない。方式変更・対象条件の限定・追加調査のどれを選ぶか返す |

探索の終了は、選んだケースが測定済み/失敗/判断待ち/対象外に分類され、証拠と次の判断が揃うこと。差なし・失敗を理由に複数端末統合の核を自動削除しない。全技術項目の成功を待たず、観測された価値と障害をP4の材料にする。

## 7. 合格値と未決定事項

P1〜P3は探索。時刻の許容差や認識率の製品合格値を発明せず、件数と誤差を報告する。誤った発言に結び付く時間差は大小にかかわらず、そのケースの機能的失敗とする。

P4で最終確認データを見る前に、対象条件ごとの重要事項回復、誤帰属、誤統合/見逃し/保留、待ち時間、手動負担、対象録音時間・規模・費用の基準を合意する。探索実測と利用場面の要求から候補を提示する。確定した共有方針違反は別枠で扱う。

| 時点 | 必要な判断・情報 | 進め方 |
|---|---|---|
| P0 | 端末・アプリ・形式、保管先、利用者/閲覧者、転送/同期状態 | iPhone 16とAndroidの既存候補を確認。確認済みの条件は再質問しない |
| 自動処理の準備前 | O03/O07/O08: データ・処理場所・保持・利用範囲 | PC内の既存実験条件で可能な候補から検討。外部処理や条件変更の部分だけ別判断 |
| 識別/終了/共有の合否前 | O04/O05/O06/O08/O09 | 帰属、曖昧時、未導入者、停止/切断、職場権限の期待動作を決める |
| P4 | O01/O02/O10と関連O03〜O09 | MVP・デモ・端末/方式・品質条件をユーザーが選ぶ。試験条件を製品仕様へ転用しない |

音声条件は[VALIDATION](VALIDATION_20260912.md)を参照。PC内処理・架空会話・検証終了後7日以内の音声等削除を維持。生音声・転記・特徴量をCodexやリポジトリへ載せない。端末原本・派生物・同期/バックアップも削除管理に含め、実験条件を製品方針へ広げない。

## 9. 成果物・担当・開始点

最初の実施単位は[最初の音声検証](FIRST_AUDIO_CHECK.md)を参照。P0/P1の具体手順・記録様式であり、自動処理の全項目や製品の合格値を追加確定するものではない。

1. ケース一覧: 小項目ごとに未実行/測定済み/失敗/判断待ち/対象外、証拠ID、理由、次の行動。
2. 比較表: 単独、人、自動処理、手動介入の差。失敗と未判定も記載。
3. MVP判断資料: 成立条件、未解決、価値、実装の残作業、必要な判断。

主担当が条件・分岐・統合を管理。入出力と完了条件が独立した調査やレビューを別エージェントへ委任する。実音声評価はPC内、別エージェントにも音声・転記を渡さない。

実行する場合の入口はP0。既存準備を再利用し不足だけ具体化する。長時間・共有の全試験を先に必須化しない。新しい失敗種別は該当項目と再発ケースへ追記して版を更新する。

今回の成果は計画書。製品方針、V項目、ローカル実験READMEとコードを確認した。人工信号6テスト成功は過去記録で今回再実行なし。録音、実装・方式比較、音声送信、commit・pushは未実施。
