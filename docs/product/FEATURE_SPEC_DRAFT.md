## 1. 2つの利用体験

### 通常の会話: 日常の「あの話」を取り戻す

SC04を使用。AとBが友人との集まりで各自の記録を開始する。会話後に統合された会話の一覧から振り返り、案・約束・思い出とその背景を取り戻す。議題や固定グループを必須にしない（D01〜D07）。

| 段階 | 操作・表示の案 | 期待する振る舞い |
|---|---|---|
| 開始 | ホームの「記録を始める」を押す。通常モードや共有相手を選ばない | D01の本人開始は維持。通常の会話にも自動統合・共有があることを伝え、「自分だけの非公開録音」と誤解させない |
| 記録中 | 記録中表示・経過時間・終了操作 | 本人の記録状態が分かる。録音が止まったら継続中と表示しない |
| 対応付け | 準備中・確認が必要・利用可能を区別 | 双方の継続承認がある明確な対応は自動共有。それ以外は会話ごとに共有確認。曖昧な対応も確認 |
| 振り返り | 会話一覧→要点→元の発言と前後 | 誰が何を話したかを確認でき、不明な帰属は断定しない。案と確定した約束を区別 |
| 途中参加 | Cに見える範囲で一覧・要点・根拠を表示 | Cの初発言前はCへ出さない。当時参加したA/Bには維持（D09/D17） |

近くの端末が同じ音を拾うことだけでは共有先を確定しない。会話の対応、本人と端末の帰属、参加区間を別に評価する（S03/O04）。

### グループ: 前回の経緯から続きを始める

継続する学生の制作チームや仲間を使用。グループ作成・加入後、集まるときにそのグループ用の記録を開始する。次の集まりで過去の会話から案・理由・懸念を取り戻す（D11/D12/S04）。

| 段階 | 操作・表示の案 | 期待する振る舞い |
|---|---|---|
| 作成・参加 | 名前を付けて作成し、招待を受けた人が加入を選ぶ | 作成者・参加者と共有方針が分かる。招待された時点ではまだ加入扱いにしない |
| 開始 | グループを選び「このグループで記録」を押す | 開始前と記録中に共有先を示す。通常記録を所属だけで取り込まない |
| 蓄積 | グループの履歴に会話単位で表示 | 別の日の会話を同一会話へ結合しない。同一会話内の複数端末統合は別の処理 |
| 次の集まり | 前回の会話を開き、今回の会話へ戻る | 発言と根拠から前回の案・今回の変更を追える。自動差分生成は初期必須にしない |
| 欠席・加入・退出 | 閲覧可能な会話とメンバー状態を表示 | 通常共有の初発言条件を一律転用せず、S04の確定した3ケースに従う。招待・再加入・管理手順は未決定 |

グループの一覧に並べることと、関連した複数会話を検索・要約することも分ける。後者を採用する場合は、入力する全会話に閲覧権限を適用する。

## 2. 画面・操作のたたき台

| 画面 | 必要な情報・操作 | 空・失敗・境界時 |
|---|---|---|
| ホーム／会話一覧 | 通常記録の開始、グループ一覧への入口、自分が閲覧できる会話、日時と短い手掛かり | 記録ゼロなら開始方法を示す。未閲覧の情報をタイトル・要点で漏らさない |
| 開始・記録中 | 通常／指定グループ、記録と共有の説明、開始、経過時間、本人の記録終了 | マイク許可なし・保存失敗は開始成功にしない。中断は取得できた範囲と分ける |
| 会話詳細 | 処理状態、要点、発言者、元発言と前後、見えている範囲、問題の報告・削除への入口 | 処理失敗・不明・未決定を区別。無音や有効な発言なしで内容を作らない |

| 確認・管理 | 曖昧な対応付けの確認、招待の取消、記録の削除・訂正報告 | 回答不一致や未回答を成功扱いにしない。権限のない操作を受け付けない |

これは情報と操作のまとまりであり、6ページを固定するUI決定ではない。画面配置・装飾・プラットフォームは別途設計する。自由質問・音声再生・写真連携・外部送信は追加候補。

欠席・途中加入・退出後の閲覧停止は2026-09-12に採用済み。管理者の退出手順等は分離し、その他は未採用の推奨として残す。D14に従いMVPは検証後に決める。

| 関連O | 推奨案 | 理由・代替との違い |
|---|---|---|

| S04 欠席者（確定） | 記録された時点で加入していた現メンバーには、欠席でもグループ用記録を共有 | 継続するチームの文脈を揃えるため。2026-09-12ユーザー了承 |
| S04 途中加入（確定） | 加入時点以降のグループ用記録の区間だけを閲覧。加入前の過去履歴は共有しない | 2026-09-12ユーザー了承。録音中の加入も加入時刻で区切る |
| S04 退出（確定） | グループ退出後は、そのグループ経由の過去・新規記録の閲覧を停止 | 2026-09-12ユーザー了承。記録削除とは別。会話からの離脱とグループ退出を混同しない |

| O05 曖昧な判定 | 対応候補の記録所有者へ確認を出し、必要な当事者全員が一致するまで、その曖昧な候補の自動統合・新たな共有を保留。否定・不一致は未統合で残す | 確認者1人の誤りで他者へ共有しない。対応判定の確認とは別に、継続承認がない相手には明確なケースでも毎回共有確認する。本人帰属の確認も別途必要 |
| O03/O07 保持 | 初期製品案は原音再生を含めず、原音は必要な照合・確認・統合を含む処理成功後に削除。失敗・未完了の原音は記録終了から最大7日で削除。文字記録は本人が削除するまで保持 | 再処理・再生とのトレードオフを明示。ここでの7日は製品の提案値であり、既存実験の削除方針を転用した決定ではない。全原音保持や文字も期限付きにする案は別比較 |
| O07 削除・訂正 | 本人は自分の記録を削除できる。統合物・要点等はその記録への依存を外して更新し、更新中は該当出力を見せない。本人の入力文字の訂正は訂正者・訂正箇所を区別し、他者の入力や統合結果への指摘は問題報告に分ける | 他人の独立記録まで削除するとは約束しない。同じ内容が別の有効な記録にもあれば残る場合を説明。グループ管理者による全員分削除は初期案に入れない |

確定した3ケースでは、グループ用の閲覧は現在の所属と加入時点以降の区間を条件にする。元発言、タイトル、要点、採用した検索・AI出力にも適用する。再加入の場合に新しい加入期間だけを対象とし、過去の期間への閲覧を自動復活させない扱いは未採用の推奨であり、O09で別途判断する。

グループ用に取得した自分の入力記録も、退出後にアプリ内の別経路から当該グループの履歴として閲覧できる仕様にはしない案。端末原本や既に持ち出されたコピーの回収は保証せず、原音の保存経路・権限と共に説明する。通常記録の正当な閲覧権限はグループ退出だけでは変えない。

原音・文字の保存先、処理場所、バックアップや削除の完了期限はO03/O07の別判断が必要。上の案を承認しても、それらを黙ってクラウド処理・永久保存・即時完全消去に確定しない。最大7日の削除と再処理不能を含む挙動は、実現可能な処理経路で検証する。

原音削除の「処理成功」は、採用方式でその原音を必要とする照合・確認・統合が完了し、権限に沿った出力が利用可能になった状態とする案。文字起こし完了だけでは原音を削除しない。確認待ちでも7日期限は延長せず、原音削除で確認・再処理の材料を失った候補は「期限切れ・再取得が必要」と表示する。遅れて回答しても成立不能な処理や自動共有を再開しない。原音なしで成立できる処理の条件は方式選定時に検証し、未検証のまま可能としない。

訂正は本人の入力文字に限定する案で、原音そのものや他者の入力を変更しない。本人訂正も本人確認・話者帰属や閲覧権限の証拠を置き換えず、統合結果は有効な根拠から再評価する。AがBの発言・統合結果へ報告した場合は、未確認の指摘として記録し、報告だけで全員の確定内容を上書きしない。指摘の内容自体も閲覧範囲外へ表示しない。複数人の報告の採否・競合解消はS05/O07の別判断とし、初期案では未確認報告から自動訂正しない。

近距離通信による退出検知、短い切断の猶予、未導入者の本人識別、録音への参加意思の具体操作、同一会話の候補探索範囲はO04/O06/O08の技術・体験検証に依存する。ここが未確定なら、推測した区間で実利用の自動共有を開始しない。独立した人工データの権限確認は進められる。

## 4. 状態と入出力の契約案

### 通常はそのまま記録、グループだけ明示選択

2026-09-12更新: ユーザーが通常の会話には設定を求めず、履歴が重なった相手と自動統合する体験を明示。通常/グループの選択を毎回要求する旧案を修正する。録音開始はD01の本人操作を前提とし、停止境界・具体UI・判定方式は引き続き案。S04の確定した3ケースは維持。

**推奨する開始方法:** ホームの主ボタンは「記録を始める」。通常モード・相手・会話ルームを選ばず、そのまま本人の記録を始める。グループで残したいときだけ別の「グループで記録」から選ぶか、グループ詳細の「このグループで記録」を押す。グループ名を開始前に示し、前回のグループへ黙って引き継がない。

| 開始画面の選択肢 | 説明文の案 | 開始条件 |
|---|---|---|
| 記録を始める（通常の入口） | 「一緒に話した人の記録と自動でまとまります」 | 毎回の通常モード選択・相手指定は不要。初回説明等で参加範囲に沿う共有を伝える。判定前に共有先が確定したように見せない |
| グループ名 | 「このグループ向けに記録します。欠席したメンバーも加入期間中の記録を見られます」 | 記録開始時に所属を確認する。選択後に退出・権限喪失が判明した場合は開始せず選択に戻す |

記録中は通常/グループ名、記録状態、経過時間、「自分の記録を終了」を表示する。本人と相手への記録・共有の伝え方はO08で別途具体化し、この画面だけで参加意思の確認が完了したとは扱わない。

#### 使う人から見える自動統合のイメージ

1. AもBも、それぞれ自分の記録を開始している。相手の選択や会話ごとの招待はしない。
2. カフェ等で会話すると、その部分が両方の記録に残る。アプリが同一会話の対応区間を探す。
3. 双方の継続承認があり、同一会話と参加者の対応が明確になれば、一つの会話として自動でまとまり、各自の履歴に現れる。会話ごとの統合ボタンや承認は不要。
4. Aの記録に含まれるBとの会話の前後まで、Bへまとめて共有しない。Cが途中で初発言すれば、Cに見えるのはその時点以降（D09/D17）。
5. 継続共有が双方承認済みでない相手とは毎回共有確認を求める。継続承認済みでも判断が曖昧なら確認する。処理中は「会話を整理中」、判定後は参加者と見られる会話を表示する案。処理時期・待ち時間は未決定。

「知り合い」はこの利用場面での相手を指す。連絡先・友達登録だけで統合する意味ではない。アプリ内の友達登録を必須にしない案を推奨するが、候補端末の発見や人物・アカウントとの対応方式はO04の検証事項とする。近隣の知らない人の録音が一致するだけで共有してはならず、同じ会話・発言者・端末所有者の関係を確かめる必要がある（S03）。

「記録の重なり」は同じ現実の会話を録った対応部分。似た話題、同時刻、同じ場所、同じグループというだけでは不十分。時間差推定だけでは相手の本人確認や共有判断はできない。使う人の手順を少なくすることと、判定を省略することを分ける。

相手の記録がまだ届かなければ待機・単独の状態を示し、後から到着した記録も元の会話区間と権限で評価する案。相手が録音していない・未導入の場合の本人識別や共有は未決定（O08）で、片側だけを複数端末統合の成功にはしない。

初回のマイク許可、記録・共有の説明、本人確認等の必要な準備は別途設計する。「設定不要」は通常の会話ごとのモード選択・相手指定・グループ作成を要求しない意味として整理し、本人が知らないうちに常時録音する仕様には変更しない。

**推奨する終了方法:** 「自分の記録を終了」は一操作で本人の録音を止める。確認ダイアログを挟んで録音が続く構成にはしない。終了後は「録音は終了しました」と、保存・統合の進捗を別表示する。保存や処理に失敗した場合は成功と表示しない。

| 本人が終了した後 | 通常の会話の案 | グループ用記録 |
|---|---|---|
| 本人の録音 | 停止する | 停止する |
| 他人の録音 | 停止させない | 停止させない |
| 本人への閲覧 | その記録に対応する参加区間は終了時刻まで。終了前の区間の遅れて届く補完は対象にできる | 録音停止だけではグループから退出しない。現メンバーとしてS04の加入範囲を引き続き閲覧できる |
| 過去の記録 | 削除・共有取消にはしない | 削除・共有取消にはしない |
| 会話全体 | 本人の停止だけで全員の会話終了としない | 本人の停止だけでグループ全体の会話終了としない |

通常モードでは、その場で話し続けていても本人が停止した後の区間は本人へ追加しない案。受け取る対象は到着時刻ではなく会話内の時刻で区切る。停止後にグループ記録や別の通常記録を開始する場合、それぞれの独立した閲覧条件を適用する。物理的な離脱が先に確定していた区間を、後の停止で延長しない。離脱検知の方式はO06で未決定。

### 共有先を変えたい場合

- 記録中の共有先は固定する。通常→グループ、グループA→Bの変更は「自分の記録を終了」→新しい共有先を選択→開始の順にする。
- 前の記録を遡って別グループへ移さない。前後の記録は別として残し、間の未録音区間を録音済みと表示しない。停止の取り消しで同じ記録を復活させず、新規記録として再開する。
- 同じ現実の会話でも、通常用・グループ用・異なるグループ用の入力は、初期案では共有先をまたいで統合・補完しない。同一会話の候補が一致しても共有先を広げる根拠にしない。共有先をまたぐ補完は、入力の利用範囲を別途設計してから検討する。
- グループ用記録の開始後に退出が判明した場合、当該記録は継続せず終了扱いにする案。退出後の区間をそのグループへ追加せず、通常モードへ自動切替もしない。実際に判明が遅れた場合の退出以後の入力はグループ出力に利用しない。本人のグループ経由閲覧はS04に従い停止する。

共有先をまたぐ統合を初期案で除くのは、所属だけで個人記録を共有しないD12を守りながら振る舞いを単純にするため。一方、同じ会話でも利用者の選択が異なると補完できない制約があるため、開始時の理解とV04の比較で負担・品質への影響を確認する。

### 共通の契約案

- 記録は本人・開始/終了時刻・通常/指定グループ・入力の由来を区別する。会話への対応付けと参加/加入区間は別情報として扱う。

- 再試行・同じ入力の再投入で二重の会話を作らない。片側しか揃わない場合は単独記録と明示し、複数統合の成功表示にしない。
- 公開API、DBスキーマ、認証・招待方式、保存・処理基盤は今回固定しない。上の振る舞いから方式候補を比較し、採用後に具体的なインターフェースを定める。

## 7. 開始の手軽さと共有許可の仕様案

状態: 毎回の共有確認と任意の双方継続承認・解除は採用済み。QR・複数人の扱い・取消の詳細などは提案。目的は、記録を始める手間を抑えながら、意図しない相手へ記録を渡さないこと。関連D01/D04〜D09/D12/D17、S03、O04/O05/O08。会話一致・参加者の識別が成功しても、共有を望むとは限らない。

### 選択肢とリスク

| 案 | 利用者の手間 | 残る問題・評価 |
|---|---|---|
| 未承認の相手とも一致すれば自動共有 | 開始だけ | 隣席の録音、再生された会話、会話に加わった初対面の相手などへ意図せず共有するおそれ。高精度の照合だけでは共有意思を証明できず、非推奨 |
| 友達登録完了後だけ記録開始 | 最初の録音前に登録作業 | 相手の導入・登録待ちで個人の記録まで遅れる。友達という関係も全会話の共有許可とは限らず、非推奨 |
| 記録はすぐ開始、新しい相手との共有だけ双方が許可 | 初回共有時の確認。継続許可後は毎回不要 | 推奨。共有の許可関係は必要だが、録音前の友達登録、連絡先取り込み、友達一覧の整備を必須にしない |

リスクの発生率は未測定。共有される情報には本文だけでなく、相手の名前、会話の存在、日時、要点・検索結果・AI回答も含む。一度相手が読んだ内容は取消で記憶や持ち出したコピーまで回収できないため、許可前に出さないことを重視する。

### 推奨する利用体験

1. **まず記録する。** ホームの「記録を始める」から本人の記録を開始。共有相手の準備は不要。共有許可がない間は、自分の入力だけから作る個人の記録として利用できる。他人の録音を先に補完・要約へ取り込まない。録音への参加意思・未導入者の扱いはO08として別に解決し、この操作で全員の録音同意が取れたとは扱わない。
2. **初めて一緒に残す相手と、その場で共有をつなぐ。** 「一緒に残す」から相手にQR等を見せ、互いに相手の表示を確認して許可するUIを候補とする。録音中でも終了後でもよく、開始を妨げない。QR読取だけでは成立せず、提示側も相手を確認する。近隣の未承認ユーザー一覧や録音内容を使った招待通知は出さない。招待は期限付き・一度限り・確認した相手に限定する案で、期限・認証方式は未決定。
3. **共有範囲を選ぶ。** 初期値は「今回の会話だけ」。別の明示操作で「今後も、この人と一緒に記録した会話を自動共有」を選べる。片方だけが継続を選んだ場合は今回限り。無回答・拒否・期限切れでは共有しない。画面に「この人の全履歴は共有されません」と示す。許可の前後を問わず今回の対象区間を示し、その会話の正当な参加区間だけを許可する。過去の別会話へ遡及しない。
4. **次回は記録開始だけ。** 双方の継続許可が有効で、同一会話・本人帰属・参加区間も確認できた場合だけ自動統合・共有する。会うたびのQRやルーム作成は不要。継続許可だけで、不参加の会話や本人停止後の区間を追加しない。照合が曖昧なら従来どおり保留する。
5. **共有状態を見て止められる。** 記録中・詳細に「共有相手なし」「Bさんと共有」等の確認済み状態と「この記録の共有を止める」を表示する案。停止操作が処理先へ反映された時点から該当許可による閲覧・新規共有を止め、派生出力も遮断して再生成する。録音停止とは別操作。オフラインでは取消完了と表示せず、反映待ちとする。相手ごとの継続許可の取消は将来の自動共有を止め、過去の個別許可を消す操作とは区別する。コピーの回収は保証しない。

初回説明の案: 「まず自分の記録として残せます。相手と共有を許可すると、一緒に話した部分がまとまります。」継続許可がある場合の表示案: 「共有を許可した相手との会話は自動で共有されます。」個人記録が便利に使えることを保ち、共有確認の未完了でアプリ全体を止めない。

### 複数人とグループの境界

- AとB、BとCの許可から、AとCの許可を推定しない。許可関係を友達の友達へ広げない。
- 初期案では共有対象区間の参加者全員について必要な相互許可が揃った区間だけを統合共有する。Cの初発言後の区間に許可不足があるならその区間を保留し、Cが来る前の許可済みA/Bの区間は維持する。Cへ参加前を渡さない。1回の複数人確認画面で全員を示すUIは可能だが、一人が他人を代理承認しない。
- 未承認・未識別の参加者が混じる区間を、音声分離や要約だけで安全になったとして公開しない。参加者・区間の検出自体が未検証であり、見逃しをゼロと保証しない。未導入者を含む共有条件はO08の未決定として、その区間の自動共有を実利用へ解放する前に解決する。
- グループ加入は、そのグループ用の共有に適用する。同じグループという理由で通常共有の継続許可を作らない。欠席・途中加入・退出の採用済みS04は維持する。
- 共有取消後も相手自身の独立入力や別の有効な許可による閲覧は別評価となる。他人の入力の消去を約束せず、未許可の入力が別経路へ流れることも許さない。

### 検証する条件と採用判断

自動共有の条件は「同一会話 × 本人・参加区間の確認 × 双方の有効な共有許可」。許可不明は共有不可とし、本文・要点・検索・AI回答・通知など全経路で確認する。これは[OWASPの認可設計原則](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)の拒否を初期値にする考え方と、各リクエストでの権限確認を参考にした設計案であり、QRやこのUIが同資料の要求という意味ではない。

採用後の人工データ確認ケース（いずれも未実行）:

| 条件 | 期待結果 |
|---|---|
| 隣席・再生音で高い一致、共有許可なし | 本文・他人の録音由来の補完・候補の個人情報を出さない |
| QRを第三者が読み取る／双方確認前／期限後に再利用 | 読取だけで共有成立しない。拒否・未回答で内容を漏らさない |
| 今回だけ双方許可、または片方だけ継続許可 | 今回の許可対象のみ。次回・過去の別会話へ自動共有しない |
| 双方継続許可あり、同一会話を確実に対応付け | 会話ごとの操作不要で許可区間を共有。別の会話の一致だけでは共有しない |
| Cが途中参加、A/C未許可 | C以降の許可不足区間は保留。A/Bのそれ以前の閲覧維持、Cへは不可 |
| 取消後に遅着入力・キャッシュ・AI回答を取得 | 無効な許可で新規共有・派生物提供を再開しない。オフライン取消を完了扱いしない |
| グループの関係だけあり、通常記録を作成 | 通常の継続許可を生成せず、グループへも流さない |

利用体験は「初回、友人との2回目、初対面が混じる集まり」を画面案で確認する。記録開始までの手順・離脱、誰に何が共有されるかの理解、初回確認の負担、次回の操作数を観測する。合格値と利用価値は未検証であり、この方式が定着につながるとは断定しない。

## 8. 共有確認・継続承認・解除の画面案

ユーザーからの理解確認: 選択は「共有前の確認を毎回挟むか」という観点で示し、双方が自動共有を選んだ場合だけ継続共有を有効にする。双方の承認前は共有されないこと、自動共有の解除で過去の共有は消えないことについて「はい」と回答あり。現在の依頼者による理解確認であり、2人の操作観測や一般利用者の使いやすさ検証が完了したとは扱わない。共有の基本方針の再確認を次工程の前提にしない。

操作できる[画面試作](prototypes/sharing.html)を追加。HTTP経由で開くES module形式。架空の2人・照合済みの区間を使い、毎回確認→双方継続承認→次回自動共有→解除を試す。製品の認可実装ではない。状態遷移の確認は `node --test docs/product/prototypes/sharing-state.test.mjs`。

### 画面1: 今回の共有を確認する

会話詳細の「共有を確認」から開くシート案。本人が選んだ相手との接続が確認できてから表示し、未承認の近隣人物を自動で一覧にしない。初対面の相手をつなぐQR等は候補のまま。既に接続した相手との毎回確認でQRを再要求するかは、認証・候補発見の方式に応じて設計し、毎回必須にはしない。

```text
Bさんと、この会話を共有しますか？

[相手の表示名・識別用アイコン]
共有する範囲：今日 14:10〜14:32
一緒に話したと確認できた部分だけを共有します。
前後の会話や、他の履歴は共有されません。

□ 今後もBさんとの会話を自動共有する
  双方が選ぶと、次回から共有の確認を省けます。
  録音は毎回、自分で開始します。後から解除できます。

[ この範囲の共有を許可 ]
[ 今回は共有しない ]             あとで
```

- チェックは初期OFF。今回の許可だけなら主ボタン1回。継続承認は追加の1操作とし、別の設定画面への移動を要求しない。「認証」ではなく「共有を許可」と表示し、本人確認と共有意思を混同しない。
- 相手名だけで本人と断定しない。識別情報は相手が接続時に提示したものを使い、他人の録音から得た名前・写真・会話内容を許可前に表示しない。範囲は自分の記録で確認できる情報に限定し、他人由来の要点は出さない。
- この例は終了した会話の確定範囲。録音中に開く場合も、今回許可するのは画面で示した確定区間までとする提案。会話が伸びた分は今回限りの許可を黙って拡張せず、継続承認がない限り追加確認する。確認回数を減らすため通常の提示は記録終了後を推奨し、録音を妨げるダイアログを自動表示しない。
- 区間が確認できない場合は「共有する範囲を確認中」とし、許可ボタンを無効にする。許可後に対象人物・区間が変わる場合は、その許可を新しい対象へ流用しない。
- 「あとで」やシートを閉じる操作は未回答。個人の記録は利用でき、共有は開始しない。「今回は共有しない」はその依頼を終了し、継続承認も作らない。同じ依頼を自動で繰り返し通知しない。

### 画面2: 共有の状態を確認する

本人が許可を送っても即座に「共有済み」と表示しない。会話詳細の同じ場所で状態を更新する。

| 状態 | 表示文言の案 | 操作と結果 |
|---|---|---|
| 自分は許可、相手は未回答 | 「Bさんの確認待ちです。まだ共有していません」 | 「今回の許可を取り消す」。閉じても録音・個人記録は継続可能 |
| 双方許可、処理中 | 「共有する会話を整理しています」 | 共有済み・利用可能とは表示しない |
| 今回だけ共有成立 | 「この範囲をBさんと共有中」「次回は共有前に確認します」 | 「共有の設定を見る」から相手別の状態へ |
| 双方の継続承認も成立 | 「Bさんとの自動共有が有効です」「一緒に記録した会話だけが対象です」 | 「自動共有を管理」 |
| 自分だけ継続を選択、双方今回許可 | 「今回は共有中」「自動共有は未成立です。次回も確認します」 | 自動共有ONに見せない |
| 未回答のまま期限切れ／拒否 | 「今回は共有していません」 | 必要なら本人から新しい確認を開始。拒否理由や相手の詳細な設定は出さない |
| 通信失敗・送信中 | 「許可を送信できていません」／「送信中」 | 再試行。通信成功前に共有成立を表示しない |

今回の許可と継続承認を別々に保存する設計案。片側だけの継続選択は今回の確認に限って待機し、不成立で終われば次回の初期値をOFFへ戻す。過去の片側選択と将来の相手の選択を組み合わせて、本人が知らない時点で継続承認を成立させない。待機期限の数値は未決定。

### 画面3: 相手ごとの自動共有を解除する

入口は会話詳細の「自動共有を管理」と、設定の「自動共有する相手」。記録開始時にこの一覧の整備を求めない。相手ごとに双方の承認が有効かを表示する。

```text
Bさんとの自動共有

自動共有：有効
一緒に記録した会話を、確認なしで共有します。

[ 自動共有を解除 ]
```

解除ボタン後の確認シート案:

```text
Bさんとの自動共有を解除しますか？

解除が反映されると、新たに共有する内容は
毎回、双方の確認が必要になります。
すでに共有した記録は、この操作では取り消しません。
録音は停止しません。

[ 解除する ]    [ 戻る ]
```

- 片方の解除で双方の自動共有条件を無効にし、相手の承認は不要。反映成功後に「解除しました。次回から共有前に確認します」と表示する。
- 通信断では「解除の反映待ちです。自動共有の停止はまだ確認できていません」。端末が送る新しい共有入力は止める案だが、処理先の停止を確認するまで完了とはしない。再試行で解除を重複・取消しない。
- 解除反映後の新規共有は、録音済み・処理待ち・遅着の入力も含めて毎回確認へ戻す案。別途有効な今回限りの許可がある区間はその範囲だけ扱う。解除前に共有済みの記録へ遡及削除をしない。
- 再有効化は双方の新しい継続承認を必要とし、残った片側の旧承認だけで復活させない。
- 「この記録の共有を取り消す」は別の操作・未採用詳細。今回の自動共有解除画面に混ぜない。これにより過去の共有が消えると誤解させない。
