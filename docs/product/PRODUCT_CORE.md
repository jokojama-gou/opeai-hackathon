## 1. 目的と文化の構想 [確定]

日常の会話には、予定された会議に限らず、突発的なアイデア、約束、予定、口頭指示、判断理由、思い出となるやり取りが含まれる。それらを記録し、後から人とAIが文脈を保ったまま利用できるようにする。

目指す長期的な変化は、友人との食事や雑談でも、写真を撮るように自然に会話を記録する文化が生まれること。これは現時点の普及状況についての主張ではなく、創業者の目指す未来である。

「みんなで使う」は中核思想。各自の記録を持ち寄り、一つの会話として統合し、参加者が共通の文脈を利用できるようにする。個人録音アプリへの共有ボタン追加だけでは、この思想を満たさない。

今回のハッカソンでは、会議の枠組みを超えて日常の会話をもっと記録しようと思える、2C向けアプリを目指す。写真を撮るように会話を残す文化を後押しすることを、今回作る体験の中心に置く。友人との雑談・食事・遊びで生まれるアイデア、約束、思い出は利用場面の候補。今回の対象場面・機能・MVPはMVP_SPECで採用済み。将来の拡張は同書の後続範囲として区別する。

2026-09-12更新: ユーザーが、現場向け2Bは「それも実現できる」という応用可能性として示し、今回のハッカソンは日常の記録文化を後押しする2Cを目指すと明示。2026-09-11の現場優先の位置付けを更新した。現場の決め事・変更・理由の振り返りと会社での履歴保持は応用シナリオとして残すが、今回の必須機能とはしない。日常の記録開始・振り返り・再利用の体験を検討し、文化の普及自体を短いデモで実証したとは扱わない。詳細は[利用シナリオと成功条件](SCENARIOS_AND_SUCCESS.md)を参照する。

## 2. 原体験と提供価値

### 原資料に記載された体験

- 対面で3人が話した打ち合わせを1人のGoogle Meetから記録した際、議事録で全員の発言が同じ利用者の発言として扱われた。これはチームの体験であり、全議事録製品の一般的性質として扱わない。
- 友人との会話で出た案や約束を後から思い出せず、会話の価値が次の行動につながらない。
- 日常で録音を始めると相手が驚く、というユーザーの体験が文化の構想につながっている。

### ユーザーが支持した価値 [確定]

1. 誰が何を言ったかを後から確認できる。
2. 発言者と背景を保った記録を、後からAIにも活用できる。
3. 現場で頼まれた作業の内容と理由を、相手に聞き直さず確認できる。
4. 自分の振り返りや、単純な思い出としても残せる。

### 追加の利用仮説 [提案・未採用]

熟練者の判断理由の復習、引き継ぎの変更点整理、共同開発の意思決定の経緯、雑談のアイデアの発展、旅行の約束の確認、写真と会話を併せた回想。これらをすべて初期機能にしない。

## 3. 概念の定義

| 概念 | 意味 |
|---|---|
| 個人の記録時間 | 本人が開始してから停止するまでの録音時間。勤務や集まりなど、ひと続きの時間を想定 |
| 同一会話 | 同じ現実の会話を複数端末が記録したもの。似た話題について別々に話した記録とは異なる |
| 統合 | 同一会話の複数の記録を対応付け、重複や欠落・品質差を扱い、一つの履歴へまとめること |
| 参加者 | 通常の自動共有で、実際に発言した人。黙って聞いていただけの人は対象に含めなくてよい |
| 共通の会話ノート | 参加者が利用する統合記録。ただし全員がすべての時間帯を見られるという意味ではない |
| グループ用記録 | 学生の制作チームや職場など、継続して集まる仲間の指定グループ向けに明示的に開始する記録。従来の職場用記録を含む |
| 近距離通信 | 会話開始時に近接の通信関係を作り、離脱の検知に使う構想。Bluetoothは例示で、採用方式ではない |

個人の録音時間、会話の区間、参加者ごとの共有可能区間を同一視しない。

## 5. 会話区間と共有の例

### D17 派生情報にも閲覧者ごとの共有範囲を適用する [確定]

通常共有では、Cの参加前の会話をC向けの要約・検索結果・AI回答にも含めない。その区間に参加していたA・Bは、その内容を引き続き利用できる。Cへの制限を共通記録全体の削除やA・Bへの制限として実装しない。

途中参加者にも共有するグループ機能を利用している場合は、そのグループの共有ルールを適用する。通常記録を所属だけでグループへ流さないD12は維持する。グループの欠席・途中加入・退出の閲覧範囲はS04、再加入等の未決定事項はO09を参照する。

根拠: 2026-09-11、ユーザーがU1に回答。通常共有の要約・検索回答からC参加前の内容を除外し、当時参加していたA・Bには含めると明示。外部出力の具体仕様や処理方式はこの回答で確定していない。

### S01 AとBだけの会話

AとBの記録に同一会話がある。Cが共通の友人でも、所属や人間関係だけを根拠にCへ共有しない。

### S02 Cが途中で発言

t0: AとBの会話開始。t1: Cがその場に来て聞く。t2: Cが初めて発言。t3: Cが離れる。

通常共有におけるCの開始境界はt2。t0〜t2の内容をCへ遡及共有しない。t3で終了を検知する方式は技術検証が必要。D17に従い、C向けの要約・検索結果・AI回答にもt0〜t2の内容を含めない。A・Bには自分たちが参加した同区間を含めてよい。グループ共有はS04/O09を参照する。

### S03 近くにいる人の端末が音声を拾う

録音の一致だけで正当な参加者と断定しない。黙っていたCの端末が拾ったことだけを根拠にCへ共有しない。MVPでは既知の2人が手動で本人帰属と参加範囲を確認する（MVP_SPEC §3/6）。自動帰属の方式・精度は後続の検証対象。

### S04 グループ用記録（職場用を含む）

Aが制作チームや職場のグループに所属していても、通常の個人記録は自動でグループに流れない。指定グループ用として明示的に開始した記録をグループで共有する。通常共有の「発言者のみ」という条件をグループ共有へ自動適用しない。

2026-09-12確定: ユーザーが提示した3ケースの対応を了承。

- 欠席した現メンバーは、加入期間中のグループ用記録を閲覧できる。
- 途中加入者は、加入時点以降のグループ用記録の区間から閲覧できる。加入前は対象外。録音中の加入も区間を分ける。
- 退出後は、過去分も含めてそのグループ経由の閲覧を停止する。ここでいう退出はグループからの退出であり、その日の会話からの離脱ではない。

この閲覧範囲を元記録と派生出力にも適用する。管理者の引き継ぎ、最後の1人の退出、招待と本人承認は後続回答でMVP_SPEC §19.7へ採用。再加入時の過去権限の復活、本人の入力記録の別経路での閲覧、保持・削除の残る詳細は必要なO項目で決める。通常共有の正当な閲覧をグループ退出だけで変更しない。

2026-09-12: ユーザーが継続して集まるチームへの支援を明示し、グループ機能を2Cの継続利用にも位置付ける方針を了承。既存の「職場用」はグループ用の一例として扱う。別の日の会話を同一会話として統合することと、同じグループの履歴にまとめることは区別する。詳細な画面・招待・記録後の移動や共有切替は未決定。

### S05 記録の食い違い

A側とB側で文字起こしが異なる場合、統合で正しい結果が必ず得られるとは仮定しない。MVPの表示・訂正・他者への指摘はMVP_SPEC §4〜6で採用。発言・推定・AIによる解釈を区別する。

## 6. 技術構想と検証すべき前提

原資料の構想は、事前声紋登録、有音区間検出、本人の声の照合、文字起こし、時刻補正、複数ログの結合。「Gitのように」は独立した記録を対応付ける比喩であり、Git・CRDT・P2Pの採用指示ではない。

以下は未検証。採用や性能を約束しない。

- 短い発言・同時発話・騒音・距離変化での話者判定。
- 同一会話と、別の場所の似た話題の区別。
- 端末の時刻差・長時間のずれと、複数録音の対応付け。
- 複数端末が実際に欠落や誤認識を減らすか。
- 長時間録音のバッテリー、容量、発熱、バックグラウンド実行。
- 近距離通信で会話終了を適切に検知できるか。切断は退出と常に同義ではない。
- 日常の場で、本人と相手が記録に価値を感じるか。

特に、原資料の「本人以外の声は処理しない」と「他端末でよく録れた音で補完する」は調整が必要。他人の音声を早期破棄すると補完材料を失う可能性がある。音声保持・処理場所・照合方式と合わせて選ぶ。

## 8. 検証シナリオ [計画案]

同じ会話を各自の端末と中央の1台で記録し、話者取り違え、発言欠落、重複、処理時間を比較する。実データによる合格値は後で決める。

最低限検討するケース: A/Bだけ、Cが聞くだけ、Cの初発言、C退出、似た話題の別会話、短い相槌、同時発話、未導入者、通信の一時切断、手動停止、職場モード切替、判定確認への未回答。

共有の正しさは統合精度と別に検証する。MVPのAPI・派生情報・生成入力・外部予定の制約はMVP_SPECの採用条件。後続の検索にもD17を適用する。必須M18の外部公開はMVP_SPEC §20の独立した公開範囲/許可を設計し、元記録の閲覧権限を渡さない。
