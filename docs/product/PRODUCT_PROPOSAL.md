## 1. 利用者に届ける価値

**推奨する価値の表現:「一緒に話したアイデアや約束、思い出を背景ごと思い出し、会話の続きを始められる。」**

文化を作ることは私たちの目標。利用者にとっての使う理由は「あの話、何だったっけ？」を取り戻せることに置く。会議として構えず、集まりの始まりに本人が記録を始め、後から自分が見られる会話を振り返る。

| 根拠の区分 | 資料にあること | この案での扱い |
|---|---|---|
| 記載された実体験 | SC04: 以前の飲み会の内容を思い出せなかった | 主ユースケースの出発点。日常利用者全般の需要が確認済みという意味ではない |
| 支持された価値 | 発言者と背景、自分の振り返り、思い出を残す | 内容と文脈を取り戻す体験にする |
| 製品方針 | 各自の記録を持ち寄り、同一会話を統合する | 「みんなで使う」の核。単独より役立つ条件は別に検証する |
| 未検証の仮説 | 手間や抵抗より振り返る価値が大きい | 開始の動機、操作負担、再利用を測る。便利という説明だけで成立としない |

「録音を保存できる」「要約できる」だけで価値が伝わるとは仮定しない。代替として記憶、聞き直し、メモ、単独の録音を置き、何を取り戻せ、どんな手間が減るかを比較する。これは機能上の比較軸であり、特定の既存製品に機能がないという市場調査結果ではない。

## 2. 主ユースケースの選択

| 候補 | 利用したくなる瞬間 | 得たい結果 | 今回の判断案 |
|---|---|---|---|
| 友人との会話を次の機会に思い出す | 「この前、何の話で盛り上がった？」 | 案・約束・背景を取り戻して続きを話す | **主軸として推奨。** SC04の実体験につながり、決定事項のない雑談も扱える |
| 学生・仲間の雑談から企画や共同制作へつなぐ | 「あのアイデア、続きを考えよう」 | きっかけ・理由・懸念・別案を取り戻して次に進む | SC04内の有力な初期検証候補として追加する方針を了承済み。学生・起業専用にはしない |
| 一定期間活動するチームで会話を蓄積する | 「前回どこまで話した？ 今回何が変わった？」 | グループの会話履歴から経緯を取り戻す | グループ機能の方針は了承済み（D11）。学生の制作チームなど2Cの継続利用にも位置付ける。具体仕様・MVPは未決定 |
| 次の予定・約束を確認する | 「何を決めた？ まだ決めていない？」 | 提案と決定を区別し、次の行動へつなぐ | 主軸の中の確認課題にする。予定管理アプリ全体には広げない |
| 思い出そのものを楽しむ | 「あの日、どんな話をしていた？」 | 言葉や背景を振り返る | 主軸内の価値候補として確認。音声再生・写真連携などは保持方針と別に検討 |
| 現場での指示・変更を確認する | 「作業はなぜ変わった？」 | 決定と理由を正確に取り戻す | SC01の2B応用例。今回は主デモ・会社管理機能の前提にしない |

初回対象の案は、既に対面で会話する友人同士。特定の年齢・職種・学生層には限定しない。デモ候補は2人、途中参加の境界は人工の3人ケースで別確認する。これは製品の人数上限を決めるものではない。

学生・共同制作の候補は「何気ない会話から生まれた可能性を、次につなぐ」価値を具体化する。背景の確認事例と未確認の因果関係は[SC04の追加候補](SCENARIOS_AND_SUCCESS.md)を参照。日本・米国での有用性は検証仮説であり、市場や言語対応の採用ではない。会話の価値に加えて、録音への抵抗、メモとの違い、複数端末の負担を比較する。

## 3. 入口から価値を得るまで

1. **集まりで始める。** 普段は各自が「記録を始める」を押し、通常モードや相手は選ばない。グループ用だけ明示的に選ぶ。本人と相手が記録・共有を理解できる入口を用意する。参加意思の伝え方はO08の設計事項。
2. **会話を楽しむ。** 議題・議事録係・固定グループを日常利用の前提にしない。録音状態が分かり、細かな分類やメモ操作を繰り返さなくてよい体験を目指す。
3. **記録を合わせる。** 同一会話の記録を対応付け、一つの会話として振り返れるようにする。通常共有は毎回双方に確認し、双方が継続共有を承認した相手とは明確な対応区間を以後自動共有する。継続承認は解除可能。曖昧な対応は確認する（D06/D07）。対象探索・本人帰属・確認UIは未決定。
4. **後で見返す。** 会話の一覧から、気になる会話とその話題を開く。何を検索すればよいか思い出せない場合にも入口を用意する。
5. **背景に戻る。** 話題や要点から元の発言と前後へたどり、何の案だったか、決まっていたか、なぜそう話したかを確かめる。
6. **続きを始める。** 記録を見て次の会話や考えにつなげる。初回案では外部への自動送信・予定登録まで行わない。

記録終了の操作で、本人の録音・会話の終了・共有範囲のどれが変わるかはO06で区別して決める。単に停止ボタンを置いて確定した扱いにしない。

### 最初の画面構成案

「記録の開始・状態」→「会話一覧」→「会話の振り返り」の3つの主要画面を比較のたたき台にする。振り返り画面内で話題の要点と根拠へ移れる構成を推奨。状態確認・曖昧時の確認・削除等の必要な操作は、仕様確定時に加える。

一覧を先に勧める理由は、SC04の「内容を思い出せない」状況では検索語が浮かばない可能性があるため。自由質問は、一覧と根拠だけでは解決しない問いが観察された場合に追加比較する。画面数や一覧方式自体は採用済み仕様ではない。

## 4. 機能の優先候補

日常の通常共有に加え、継続する仲間にはグループ用の記録を選べる構成とする方針。グループ機能を会社管理と一括して後回しにはしない。グループの履歴では複数回の会話を区別し、同一会話内の複数端末統合とは分けて扱う。

| 優先候補 | 機能 | なぜ必要か | 実装前の判断・確認 |
|---|---|---|---|
| 核 | 本人による記録開始・状態表示・終了 | 日常で開始し、会話を妨げず残す | O02/O06/O08: 端末、停止の意味、参加意思と説明 |
| 核 | 複数記録の対応付けと統合 | 各自の記録から同じ会話を見返す | V01〜V04/O04: 誤結合、欠落・重複、話者・端末の帰属 |
| 核 | 会話一覧と振り返り | 検索語を思い出せなくても会話を取り戻す | O01: 一覧の手掛かり、誤認識や処理中・失敗時の表示 |
| 核 | 要点から元の発言・背景へ戻る | 誰の発言かを確認し、会話の意味を取り戻す。不明な帰属を断定しない | 文字起こし・話者帰属・保持・根拠の対応。音声再生は必須採用しない |
| 利用の前提 | 閲覧者と参加区間に沿った表示・共有 | 一緒に使う際に見せてはいけない内容を混ぜない | D09/D17、O04〜O06。採用する全出力経路へ適用 |
| 利用の前提 | 保持・削除と未処理／失敗の扱い | 私的な会話を扱う状態を利用者が理解・操作できる | O03/O07。実験の7日削除を製品仕様に転用しない |
| 継続利用の機能方針 | グループを指定した記録と、会話ごとの履歴 | 同じチームが前回の背景から続きを始める | 欠席・途中加入・退出の閲覧範囲はS04で確定。作成・招待・管理者・再加入等はO09で未決定。通常記録を所属だけで流さない |
| 追加候補 | 案・約束・思い出の整理 | 会話を長く読まず、価値ある箇所に気付く | 分類の押し付けや創作を検証。全会話に決定事項を要求しない |
| 後で比較 | 自由質問、音声再生、写真連携、予定登録 | 振り返りと再利用を広げる | コア体験で不足が確認されたときに選ぶ |
| 今回の主軸外 | 会社固有の管理、リアルタイム連絡 | 2Bや追加用途へ広げる | 基本のグループ機能とは区別。主軸を成立させるための必須機能にしない |

この表は価値を試すための優先案。全行を一括で実装する指示ではない。MVP最終採用はD14に従う。API、DB、技術スタックは利用体験と必要な検証から選び、先に固定しない。

## 5. 複数端末を使う意味と、成立しない場合

期待する意味は、複数の記録に残る同じ会話を一つにまとめ、片側で失われた内容や文脈を取り戻せること。ただし次の3点は別々に確かめる。

- **記録の品質:** 各単独より、両方を使うと重要な発言・背景が回復するか。改善と悪化、重複、創作を別記する。
- **本人と共有:** 音声が一致しても端末所有者や正当な参加者の証明にはならない。話者帰属・参加区間・閲覧を別に確認する。
- **使う負担:** 2人が記録を始める、処理を待つ、曖昧な箇所を確認する負担に見合う価値があるか。

単独で十分、統合で悪化する、相手が使わず成立しない場合はその結果を残す。追加価値を無理に作ったり、単独の弱い例だけを選んだりしない。日常の対象条件や方式を再検討し、複数端末統合の核を変えるなら人の明示判断へ戻す。

## 6. 仕様を絞るための確認

| 確認 | 観察・受入条件の候補 | 次に決められること |
|---|---|---|
| 記録したい動機 | 今の対処、残したい瞬間、本人と相手の抵抗を聞く | 主ユースケースと開始の体験 |
| 会話の回復 | 案・背景・約束と誰の発言かを確認できる。帰属が不明なら断定せず、未決定を決定に変えず、不明を創作しない | 一覧・要点・根拠で足りるか、質問が必要か |
| 普通の雑談 | 決定事項やToDoがなくても振り返りたいものがあるか | 会議の形式へ寄せず日常の価値が成立するか |
| 参加区間 | Cの参加前をCの要点・根拠へ出さず、A/Bには維持する | 必要な共有の契約とテスト |
| グループの継続利用 | 2回の会話を区別してたどり、前回の案と今回の変更を確認できる。通常記録を所属だけで共有しない | グループ履歴の体験と、S04で確定した欠席・途中加入・退出の閲覧を確認。実行は未実施 |
| 技術と負担 | 各単独対統合の回復・悪化・待ち時間・手動操作を比較 | 実現条件とMVPの範囲 |
| 再利用 | 次に使う具体場面と使わない理由を聞く。後日の実利用は別記 | 継続検証の価値。短期で文化定着を保証しない |

当面は製品案の採用判断と机上の体験確認を先にする。[検証準備](../development/aidd-lite/VALIDATION_PREPARATION.md)の録音ツール確認は既存成果として保持するが、端末情報の回答を製品案検討の前提にしない。

## 7. 今、採用を提案する3点

1. **価値:** 会話の内容と背景を取り戻し、続きを始められることを前面に出す。
2. **主ユースケース:** 友人との会話を次の機会に思い出す場面を入口にし、案・約束・思い出をその中で扱う。
3. **体験の優先:** 記録→複数記録の統合→会話一覧→要点と根拠の振り返りを第一候補とする。自由質問や外部連携は追加比較とする。

追加の確定方針（2026-09-12）: 継続して集まるチームを支援するグループ機能を設ける。基本のグループ用記録・会話履歴を製品案に含め、作成・招待・権限・画面の詳細と今回実装する範囲は次に具体化する。上の3点全体やMVPの最終採用をこの了承から推定しない。

この3点への判断は、MVP・採用技術・全機能実装の承認とは分ける。最終MVPは必要な価値・技術検証後に、対象端末、処理・保持、識別・共有、品質と負担を照合して確定する。未解決の問いを全部先に解決する必要はない。
