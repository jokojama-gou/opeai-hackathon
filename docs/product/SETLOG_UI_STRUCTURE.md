# Setlogを参考にしたUI構成案

版: 1.4 / 2026-09-15（構成決定: 2026-09-14）。状態: **構成案・主要8画面の静止画を作成。本文はKosugi Maru、タイトルはNoto Sans JP。既存案とは別ファイルで管理。アプリ未実装**。

ユーザーが指定した録音起点の構成と、未共有記録の扱いをまとめる。既存の[MVP_SPEC](MVP_SPEC.md)とHome検討はそのまま保持し、本書で置き換えない。個人記録の一覧は追加決定の[一覧整理](SETLOG_RECORDS_LIST.md)を優先し、画面は[画像v2](prototypes/setlog-ui/README.md)へ反映済み。Setlog案の画面配置・導線は本書、既存案の画面配置・導線はMVP_SPECを参照する。既存のAPI・共有条件・保存期限は共通の前提とし、この構成案から変更しない。

## 1. 基本方針

**お互いの確認・共有許可がそろっていない記録は、「自分の記録」にまとめて残す。** 共有しないままでも、本人が見返せる通常の記録として扱う。

相手の確認、同一会話・参加範囲の確認、双方の共有許可を区別する。接続コードを入力しただけでは共有済みにしない。記録した端末の所有者と、記録に含まれる発言の話者も区別する。

## 2. 画面構成

| 入口 | 内容と主な操作 |
|---|---|
| 録音タブ | 起動画面。大きな丸い「記録を始める」ボタンを中心に置く。相手指定・ルーム作成なしで開始でき、起動だけでは録音しない。録音中は経過時間と停止操作を表示 |
| ルームタブ | 先頭に「自分の記録」、その下に会話した相手ごとのルームを並べる |
| 自分の記録 | 本人の元記録を日付ごと・新しい順にまとめ、通常1〜2行のコンパクトな記録行から詳細を開く。今日を展開し、過去の日付は折りたたむ。共有手続きのない記録も通常の記録として表示 |
| 相手のルーム | 「記録／AI」を切り替える。初期表示は記録カード。記録面に許可範囲の共有会話、AI面に本人用の質問・参照操作を置く |
| 右上の確認アイコン | 本人の確認・回答・復旧が必要なものへの入口。本人待ちの件数を表示 |
| 左上の設定 | 設定、共有管理、サービス接続などの入口 |
| ルーム一覧のメニュー | 「すべての記録」「保存したもの」「日付から振り返る」への補助入口 |

録音画面とルーム一覧に設定・確認アイコンを置き、独立したHomeは置かない。録音中は各画面から共通録音帯で録音画面へ戻れる。停止操作、保存中、保存成功を別の状態として表示する。

```text
起動 → 録音タブ                         ルームタブ
        設定 / 確認                      設定 / 確認 / メニュー
        大きな録音開始                    自分の記録 → 個人記録の詳細
        録音中：経過時間・停止             相手のルーム
                                          ├ 記録 → 共有会話 → 出典
                                          └ AI → 参照記録・質問・出典・外部依頼

各画面 ── 共通録音帯 ──→ 録音画面
```

日付からの振り返りは選択日を見出しに表示する。会話詳細は本文を中心とし、要約・次の行動・保存など既存機能への入口を保持する。本人が採用したToDoは会話詳細と確認一覧から開けるようにし、AI処理中と本人が行う実作業を区別する。

## 3. 未共有記録の流れ

```text
録音 → 保存成功 → 自分の記録
                  ├ 個人記録として見返す
                  └ 一緒にまとめる
                     → 相手・同一会話・参加範囲の確認
                     → 双方の共有許可
                     → 許可範囲の統合処理
                     → 相手のルームに共有会話を表示
```

図は保存先と共有への分岐を示す。録音後の自動送信・自動処理を決定するものではなく、処理開始の条件は既存仕様に従う。既存の有効な双方継続許可がある場合も、その成立条件を維持する。

「自分の記録」の一覧は日付見出しでまとめ、各記録行には時刻・記録名・録音時間・保存／処理／共有手続きの状態と **「自分のみ」** を表示する。配置と折りたたみは[一覧整理](SETLOG_RECORDS_LIST.md)に従う。保存中・保存失敗を保存成功として表示しない。相手を本人が把握していても、共有前は相手別ルームへ振り分けない。相手名を推測した自動振り分けも行わない。

| 状態 | 自分の記録の表示と操作 | 本人の要対応件数 |
|---|---|---|
| 共有手続きなし | 通常の個人記録。「自分のみ」を表示し、確認バッジは付けない | 含めない |
| 本人の確認が必要 | 「共有範囲を確認」。相手・同一会話・参加範囲の必要な確認へ進む。確認一覧にも表示 | 同じ確認を一件として含める |
| 自分は確認済み・相手待ち | 「相手の回答待ち」。自分の入力と、相手の本文を含まない応答状態を表示 | 含めない |
| 許可成立・統合中 | 進捗を表示。許可成立と共有本文の完成を区別する | 通常の処理中は含めない。本人の再確認・復旧が必要なら、その操作を表示 |
| 見送り・確認期限切れ | 個人記録として残し、既存の保存期限を維持する | 期限到来だけでは含めない |

共有後も本人の元記録は「自分の記録」に保持する。相手のルームには現在閲覧できる許可範囲の共有会話を表示し、元記録全体を共有した扱いにしない。元記録の共有進捗と「自分のみ」という元記録全体の閲覧範囲を分けて表示する。

共有前の接続情報は表示名・照合コード・自分の記録・応答状態に限る。相手の日時・録音一覧・発言・要点を先に表示しない。再確認・取消・保存期限切れには、既存の本文・派生情報の閲覧制約を適用する。共有手続きの期限切れを、個人記録の削除や保存期限の延長と混同しない。

## 4. 相手のルームの「記録／AI」

「記録」は共有会話を読み返す面とする。大きな時刻付きカードから要約・本文を開き、出典へ戻れるようにする。処理待ち・失敗・本文が利用可能な状態を区別する。未共有の元記録は「自分の記録」から開く。

「AI」は本人用のワークスペースとし、参照記録のチェック、質問欄、回答と出典、外部サービスへの依頼を置く。相手本人へのDM送信や、AIの回答を相手に共有する機能にはしない。表示・参照できる記録は、現在の閲覧権限と保存期限に従う。

AI参照の初期値、新規記録を加えたときの選択、チェック変更の適用時点、過去のAI履歴を入力へ含める範囲、参照0件時の処理は別の仕様判断として残す。参照を外した内容が過去の回答経由で使われる問題も、その判断で扱う。外部サービスへの依頼入口だけで送信・登録・成功が成立したように表示しない。

## 5. 確認アイコンと共通状態

確認一覧は本人が次に操作できるものを集める。共有範囲の確認、日時などへの回答、保存・送信・接続の復旧、届いた指摘への対応などから対象の画面へ戻す。本人が採用した実作業は、確認への回答と分けて表示する。分類の前提は既存の[本人対応の整理](MVP_SPEC.md#home-attention)を参照し、Setlog案では入口を右上アイコンに置く。

共有手続きのない個人記録、相手待ち、通常のAI処理中を本人の用事として数えない。同じ原因を重複計上せず、回答・復旧結果と件数を一致させる。未取得や取得失敗を「0件」と表示しない。

| 状態 | 表示と次の操作 |
|---|---|
| 自分の記録が空 | 記録がまだないことを伝え、録音タブへ進める |
| 相手のルームがない | 「自分の記録」は常に開ける。個人記録から任意に「一緒にまとめる」へ進める |
| 絞り込み結果が0件 | 条件に合う記録がないことを示し、条件解除へ進める |
| 読込中・処理中 | 対象と進捗を表示し、空・成功と区別する |
| 保存・処理・接続失敗 | どこで止まったかを示し、利用可能な再試行・復旧操作へ戻す。未保存を保存済みにしない |
| 確認期限切れ | 個人記録へ戻れる。再開時には既存のコード・確認条件に従う |
| 原音・文字の保存期限切れ／権限外 | 利用不可の理由を示し、利用可能な記録一覧へ戻す。旧本文を表示しない |
| 録音中に別画面へ移動 | 共通録音帯に状態を示し、録音画面へ戻って停止できる |

## 6. 見た目の方向

Setlogの[公式画面例](https://setlog.kr/setlog-preview-720.png)を参考に、白〜淡い背景、丸い操作、大きな時刻付きカード、控えめなパステル色を使う。具体的な配色・余白は画像検討で決める。

本文は濃色で読みやすくし、状態は色だけで伝えない。文字拡大でも開始・停止・戻る操作が隠れず、既存の操作領域48×48以上、Glassの適用範囲と通常面への代替を維持する。

### タイトルと本文のフォント（2026-09-15決定）

ユーザー指定により、Setlog案の本文には **Kosugi Maru Regular（400）** を採用する。記録の本文・要約、AI回答、説明文に使う。

追加指定の「タイトルははっきりしたフォント」に合わせ、画面タイトル・見出し・記録カードのタイトルには **Noto Sans JP SemiBold（600）** を使う。本文との違いを明確にし、タイトルの輪郭と階層を読み取りやすくする。大きな時刻・ボタン／タブ等の短い操作ラベルの書体は今回の決定に含めない。

[公式配布のメタデータ](https://github.com/google/fonts/blob/main/apache/kosugimaru/METADATA.pb)に従い、Regular 400を使用する。本文の擬似的な太字化は行わず、読みやすさは文字サイズ・行間・余白・色で調整する。[実フォントの本文見本](prototypes/setlog-ui/kosugi-maru-body.html)では、17px・行間1.75を比較用の初期値として変更できる。最終的なアプリの寸法値ではない。

Noto Sans JPは[公式配布の可変フォント](https://github.com/google/fonts/blob/main/ofl/notosansjp/METADATA.pb)の600を使用する。[実フォントの書体見本](prototypes/setlog-ui/kosugi-maru-body.html)にタイトルと本文の組合せを反映した。[画像v1](prototypes/setlog-ui/history-v1.md)はフォント選定前の構成・配色の履歴。[画像v2](prototypes/setlog-ui/README.md)は採用書体を生成指示へ反映した現在の画面案だが、字形は近似であり実フォントの正確な組版を保証しない。

既存の[配置見本](prototypes/mvp-spec-wireframes.html)、[F系列の画面画像](prototypes/design-directions/f-screen-gallery.html)、[G系列のHome画像](prototypes/design-directions/g-ios-home-attention-v1.png)は既存案の資料として保持する。本書に対応する[Setlog案の画像と生成指示](prototypes/setlog-ui/README.md)は専用フォルダに保存した。録音・ルーム・自分の記録・記録／AI・確認・共有範囲の8画面例で、具体配色と配置は検討用の候補。空・失敗・期限切れの画像は未展開。

## 7. 確認条件と今回の範囲

構成を具体化する際には、次の点を確認する。

- 起動直後に録音開始を見つけられ、相手指定なしで開始できる。
- 保存成功後の未共有記録を「ルーム → 自分の記録」から迷わず開ける。
- 本人待ちと相手待ちを区別でき、要対応件数も一致する。
- 接続コード入力だけで共有済みにならず、共有前に相手の内容を表示しない。
- 共有後も元記録を保持し、相手のルームには許可範囲の共有会話だけを表示する。
- 録音中は各画面から共通帯で戻れる。
- 空・読込・失敗・期限切れでも次の操作が分かる。

1.0では構成案の文書化とファイル分離までを実施した。2026-09-15の追加依頼で主要8画面の静止画を作成し、1.1に参照先を追加した。1.2では本文のKosugi Maru採用と実フォントの見本、1.3ではタイトルのNoto Sans JP採用を反映した。1.4では同期後の一覧整理と画像v2への参照を統合し、録音中の経過時間・停止操作を維持して残り時間を表示しない追加決定を反映した。アプリコード・公開API／型は変更しない。録音後の自動処理、AI参照の初期値・履歴、外部実行・書出し条件、ルームの正式契約は別の仕様判断として残す。既存案との統合・置換も行わない。

文書の整合性確認を、新構成の操作・実機・録音・共有・AI・外部サービスの動作検証とは扱わない。作業結果は[WORKFLOW](../development/WORKFLOW.md)に記録する。
