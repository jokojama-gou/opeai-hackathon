PRODUCT CONCEPT · TEAM DISCUSSION · 2026.09.11

会話をみんなの
文脈として残す

それぞれの端末に残った記録を重ね合わせ、
一緒に話した時間を、人とAIが後から使えるものにする。

食事中に生まれたアイデア。何気なく交わした約束。作業の途中で教わった理由。会議以外の時間にも、残しておきたい情報があります。

私たちは、日常の会話を記録することが、写真を撮るように自然になる文化を目指しています。その入口として、口頭のやり取りが多い現場で役立つプロダクトを考えています。

02 / THE PROBLEM

話の結論だけでは、
後から分からなくなることがある

きっかけの一つは、チームの対面での打ち合わせでした。3人で話した内容を一人のGoogle Meetから記録したところ、議事録では全員の発言が同じ利用者の発言として扱われていました。

誰の提案だったかが失われると、話の背景もつかみにくくなります。その記録を後からAIへ渡しても、元の会話を十分に伝えられません。

現場で

作業の途中で指示が変わり、ミスについても話した。後から振り返ろうとしても、何を決め、何が起きたかを思い出せず、会社にも経緯が残っていない。

友人との時間で

「それ、面白いね」と盛り上がった。翌日続きを考えようとすると、何がきっかけだったか思い出せない。

残したいのは、誰が何を話し、なぜその話になったか。その背景があれば、確認も、振り返りも、次の相談も始めやすくなります。

打ち合わせの記述はチームの原体験です。既存の議事録サービス全般が同じ動作をする、という主張ではありません。

03 / THE EXPERIENCE

各自の記録から、同じ会話を見つける

記録する

本人が開始

集まりや勤務の始まりに、それぞれが録音を始める。

合わせる

同じ会話を照合

独立した記録から対応する部分を見つけ、聞こえ方の違いを補う。

使う

共通の文脈へ

参加者が会話を見返し、振り返りやAIとの相談に活用する。

通常の利用では、固定グループを先に作る必要はありません。共通の知人であることではなく、同じ会話に参加したことを共有の根拠にします。

「似た話題」と「同じ現実の会話」は別です。同一会話の判定方法と、複数端末でどの程度品質が改善するかは、これから検証します。

複数の記録を持ち寄ることが、設計の中心03 / 核となる仕組み
04 / SHARING

同じノートでも、共有する時間を分ける

AとBの会話にCが加わる場合、Cに共有するのは、Cの最初の発言からです。先にその場で聞いていたとしても、それ以前の会話へは遡りません。黙って聞いているだけの人は、通常共有の参加者に含めません。

通常共有では、Cの参加前の話はC向けの要約・検索結果・AI回答にも含めません。その時間に話していたA・Bは引き続き利用できます。途中参加者にも知らせるグループ共有を使う場合は、グループの共有ルールに従います。

通常は自動、曖昧なら確認

明確な場合は自動で統合・共有。判定が不確かなときだけ利用者に確認します。誰に何を確認するかは今後設計します。

職場用の共有も選べる

固定メンバーのグループ内で共有する使い方も想定します。所属だけで個人の記録は流れず、職場用として始めた記録に限ります。

関係の近さだけで、会話を共有しない04 / 共有の考え方
05 / VALUE

残した会話から、続きを始められる

「さっき頼まれた作業、なぜこの順番だった？」
「昨日のあのアイデア、もう少し考えたい」

発言者と背景が残っていれば、会話の後もその内容を使えます。指示の確認、自分の振り返り、思い出として残すこと、そしてAIへ文脈を引き継ぐことが、目指す価値です。

場面価値の候補位置付け
現場の口頭指示内容と理由を聞き直さず確認する支持された価値
一日の振り返り自分の会話や経験を見返す支持された価値
友人との時間思い出や背景を残し、AIにも活用する目指す展開
熟練者との作業判断理由やコツを復習する追加の利用仮説
共同制作・開発案の経緯を取り戻し、続きを考える追加の利用仮説

最初に検証するのは、土木作業や映画撮影などで口頭で交わした決め事・変更・ミスを記録し、後から振り返れる価値です。職場用の記録は会社での履歴保持にもつなげます。その場にいなかった人へのリアルタイム連絡は、そこからの応用機能です。閲覧方法や保存の仕組み、今回作る機能の範囲はこれから決めます。

将来の入口として、スマホのボタン、時計、グラスなども考えています。SNSへの統合も展開候補です。対象機器や初期対応は、まだ決めていません。

06 / DISCUSSION

この構想について、意見をください

思想はここまで揃いました。次は「本当に使いたい場面」と「技術的に成立する範囲」を照らし合わせ、ハッカソンで作るものを決めます。

今、決まっていること

本人が録音を開始すること。各自の記録を統合すること。参加者と時間に応じて共有すること。通常は自動、曖昧な場合は確認すること。

これから決めること

MVP、対象端末、音声の処理場所、保存・削除、照合と通信の方式。「完璧な履歴」は目標であり、性能保証ではありません。

  1. どの職場の、どの一場面なら、明日から使いたいですか？
    今どう対処していて、何が困るかも教えてください。
  2. 記録が残っていて助かった経験、残せず困った経験はありますか？
    「誰」「内容」「理由」のどれが必要だったでしょうか。
  3. 集まりの始めに録音し、後から会話がまとまる体験をどう感じますか？
    自分が使う側・相手が使う側の両方から考えてください。
  4. 自動統合や共有で、意図と違うことが起きそうな場面はありますか？
    途中参加、近くの別会話、通信の切断などを含めてください。

意見を残すときは「具体的な場面／困りごと／欲しい結果／気になる点」の順で書くと、次の設計につながります。
