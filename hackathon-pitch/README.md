# Codex 開発祭 2026：発表準備エージェント

今回のハッカソン専用のCodexスキル `hackathon-pitch-coach`。公式情報と実際の製品を参照し、対話で切り口を選び、スライド内容・話す原稿・デモ手順・想定QAを作成する。追加のAPIキーや専用Webサーバーは不要で、Codexの既存環境を使う。

## 使い始める

Codexで次のように依頼する。製品のパス・URLは当日渡せばよい。

> $hackathon-pitch-coach 製品は［パスまたはURL］。大会の未定項目はそのままで、まず発表の切り口を一緒に考えたい。

登録先は `C:/Users/yos57/.codex/skills/hackathon-pitch-coach`。この作業中の会話のスキル一覧には追加直後の登録が反映されない場合がある。見つからない場合は、次のようにファイルを直接指定する。

> C:/Users/yos57/home/myApp/opeai-hackathon/hackathon-pitch/skill/hackathon-pitch-coach/SKILL.md を読んで発表コーチとして始めて。製品は［パスまたはURL］。

PowerShellから起動する場合：

```powershell
& 'C:\Users\yos57\home\myApp\opeai-hackathon\hackathon-pitch\start-coach.ps1' -ProductPath '実際の製品フォルダの絶対パス'
```

`-ProductUrl`も指定可能。引数なしでも起動でき、製品の所在から対話する。`-Check`は対話を開始せず、必要ファイルとCLIの存在、指定パス・URLを確認する。モデルや承認設定は既存設定を引き継ぐ。

## 対話でできること

- 「この製品をどう見せるか、一緒に考えて」：製品を参照し、根拠のある切り口を提案。
- 「この案で原稿とデモを作って」：実際に使える台詞・操作手順まで出力。
- 「時間が決まった」「この機能は間に合わない」：関連するスライド・台詞・操作をまとめて更新。
- 「審査員役で質問して」：一問ずつ質問し、回答の改善を支援。
- 「前回の続きから」：保存した決定事項を読み、同じ説明を繰り返さず再開。

## 作業と成果物

対話の決定事項・根拠・構成は `working-draft.md` に保存する。構成ができた段階で `output/slides.md`、`output/pitch.md`、`output/demo.md`、`output/qa.md` を作成・更新する。出力は原稿・内容案のMarkdownで、PDF/PPTXの生成は最終形式の指定に応じて行う。

## 発表を考えるAIへの使い方

- 最初に大会ルールと未確認事項を読む。今回の公開情報にない時間・枚数・提出形式を公式条件として補わない。
- 当日のプロダクトを確認し、実装済み・動作確認済み・作り手の説明・将来構想を区別して扱う。
- 予選と決勝を分けて発表を設計する。大会の配点を、そのまま発表時間の配分にしない。
- スライド、話す原稿、デモ手順で同じ価値と証拠を使う。Codexの活用は、実際の試行・修正・検証の記録に基づいて説明する。
- 未確認条件がある間も、伝える内容の整理は進めてよい。時間内に収まる、提出可能、公式条件をすべて満たす、とは未確認のまま断定しない。
- 公式条件とAIの提案を分ける。追加の運営案内を受け取ったら、発行元・日時・該当箇所とともに条件を更新する。矛盾は消さずに残す。
- 当日開始時・提出前の再確認は推奨手順。自動監視は設定していない。

この資料は発表準備に必要な事項の抜粋であり、公式規約全文の代替ではない。応募・賞品・税務等の詳細は今回の保存対象から除いた。
